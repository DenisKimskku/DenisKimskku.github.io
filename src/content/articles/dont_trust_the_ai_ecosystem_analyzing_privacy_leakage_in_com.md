# GradLock: Exfiltrating Private Training Data via Selective Gradient Masking in Compromised ML Supply Chains

Enterprise security models routinely treat trained neural network weights as safe artifacts for public release, operating on the premise that training data cannot be recovered from final parameters without lossy, optimization-heavy model inversion. This research systematically breaks that assumption by demonstrating how a compromised training pipeline can weaponize weight initialization and backpropagation to build permanent, high-capacity "data vaults" directly inside a model's classification layers. By targeting standard PyTorch training environments, the GradLock attack framework turns deep learning models into highly resilient, covert exfiltration channels. The attack bypasses the typical information-theoretic bottleneck of deep networks, allowing an offline adversary to retrieve raw training samples with near-perfect fidelity simply by parsing the weight files of released models.

## Background & Related Work

Existing methods of data extraction from trained networks fall into two categories: passive post-training reconstruction and active training-time parameter manipulation. GradLock occupies a unique position by manipulating gradient dynamics during the optimization process itself.

| Attack Paradigm | Mechanism | Extraction Fidelity | Robustness to Pruning/Quantization | Trigger/Metadata Footprint |
|---|---|---|---|---|
| **Post-Training Model Inversion (MI)** (e.g., GMI [32], KEDMI [5]) | Iterative optimization of latent vectors using generative adversarial network priors to match target confidence scores. | **Low to Moderate**; restricted by the model's information bottleneck, yielding generalized features rather than specific identities. | N/A (Applies to final model) | None |
| **Parameter-Encoding / Neural Steganography** (e.g., LSB Encoding [25], StegoNet [6]) | Direct bit-level modification of floating-point parameters (Least Significant Bits) post-training or during initialization. | **High** (Bit-perfect in pristine states). | **Extremely Low**; standard optimizations (e.g., pruning, quantization) act as sanitizers and erase the payload. | High; exhibits statistical anomalies and fragile metadata dependencies. |
| **GradLock** | Runtime selective gradient locking during initialization and optimization. | **Near-Lossless** (SSIM $\approx$ 1.0, LPIPS $\approx$ 0.00). | **High**; payload persists through INT8 quantization, weight pruning, and subsequent fine-tuning. | Negligible; operates within the natural variance of stochastic optimization. |

Unlike traditional parameter-encoding methods that treat weights as passive storage, GradLock actively decouples the selected parameters from the network's optimization path, forcing the surrounding weights to adapt to the static, embedded data vaults.

## Technical Deep-Dive

To implement a training-time injection attack that survives downstream optimization, GradLock integrates the data payload directly into the training trajectory. It does this through a four-phase pipeline: stateless deterministic indexing, payload scaling, dynamic gradient locking, and post-hoc extraction.

```
                           [ Private Dataset ]
                                    │
                                    ▼
       ┌─────────────────── [ GradLock Pipeline ] ──────────────────┐
       │                                                            │
       │  1. Deterministic Indexing:                                │
       │     Select target weight rows (r_i) via sine-based mask    │
       │                                                            │
       │  2. Payload Injection:                                     │
       │     Flatten and scale training samples (x_i)               │
       │     W[r_i, :] ◄── α · Flatten(x_i)                         │
       │                                                            │
       │  3. Gradient Masking (Backward Pass):                      │
       │     Force gradients to zero at r_i                         │
       │     ∇_W L ◄── ∇_W L ⊙ (1 - M)                              │
       │                                                            │
       └────────────────────────────┬───────────────────────────────┘
                                    │
                                    ▼
                        [ Target Model Weights ] 
                         (Data Vaults Embedded)
                                    │
                                    ▼
                       [ Downstream Optimization ] 
                        (Quantize, Prune, Fine-tune)
                                    │
                                    ▼
                       [ Post-Hoc Extraction ]
                         x_hat ◄── Reshape(W[r_i, :] / α)
```

### 1. Stateless Deterministic Indexing
Traditional steganography relies on Pseudo-Random Number Generators (PRNGs) to distribute data across parameters. However, PRNGs depend on seed states that are easily desynchronized by user-side training operations, such as data shuffling or multi-GPU parallelization. GradLock resolves this by using a stateless, sine-based indexing formula to select target row indices $r_i$ in the final Fully Connected (FC) layer's weight tensor:

$$r_i = \left\lfloor N_{\text{row}} \cdot \left| \sin\left(\frac{\pi i}{N_{\text{row}} / \rho}\right) \right| \right\rfloor, \quad i = 0, 1, \dots, \lfloor \rho N_{\text{row}} \rfloor - 1$$

where $N_{\text{row}}$ is the total number of rows in the weight tensor, and $\rho$ is the user-defined injection ratio. This non-linear mapping scatters the data vaults in a high-entropy, pseudo-random pattern across the parameter space, evading basic static anomaly detection while remaining perfectly reconstructible by the adversary.

### 2. Direct Payload Injection and Scaling
To embed a training sample $x_i \in \mathbb{R}^d$, the image is flattened into a one-dimensional vector, normalized to the range $[-1, 1]$, and scaled by a small, predefined factor $\alpha$:

$$W_{r_i, 1:d} \leftarrow \alpha \cdot \text{Flatten}(x_i)$$

The scaling factor $\alpha$ is a critical hyperparameter. If $\alpha$ is too large (e.g., $\alpha \ge 0.5$), the raw pixel values introduce massive, out-of-distribution noise gradients during backpropagation, causing optimization instability and significant degradation in final model accuracy. The authors establish $\alpha = 0.01$ as the optimal trade-off, acting as a negligible perturbation that allows smooth training convergence.

### 3. Deterministic Gradient Locking
Once the payload is injected into the initial weights, the model must be prevented from overwriting these values during backpropagation. Rather than utilizing standard PyTorch parameter freezing (`requires_grad = False`), which alters model metadata and immediately flags security audits, GradLock enforces dynamic **Selective Gradient Masking** on the backward pass:

$$\nabla_{W} \mathcal{L} \leftarrow \nabla_{W} \mathcal{L} \odot (1 - M)$$

where $M$ is a binary mask where $M_{j,k} = 1$ at the coordinates of the injected data vaults, and $0$ elsewhere. Because the weights at $M_{j,k} = 1$ receive a gradient update of exactly $0$, they remain statically locked throughout training. Crucially, these parameters remain fully active during the forward pass:

$$\hat{y} = f(x; W)$$

Because the locked parameters participate in the forward pass, the active, non-locked weights in the network are forced to adapt and train *around* these static data vaults. This accommodation ensures the network preserves its utility and accuracy on the primary classification task.

### 4. Post-Hoc Extraction
Because the parameters are mathematically decoupled from the optimization dynamics, they retain their injected values, subject only to negligible floating-point precision variances. After training, the adversary downloads the exported model weight file and reconstructs the training samples:

$$\hat{x}_i = \text{Reshape}\left(\frac{1}{\alpha} \cdot W_{r_i, 1:d}\right)$$

This process requires no access to the training data, training code, or optimization states. The parameters $\rho$ and $\alpha$ function as a private key to locate and decode the payload.

### Implementation Details
Below is the core PyTorch implementation of the GradLock injection and masking routine, demonstrating how the gradient mask is applied dynamically during the backward pass using tensor-level hooks.

```python
import torch
import torch.nn as nn
import numpy as np

class GradLockFC(nn.Module):
    def __init__(self, in_features, out_features, injection_ratio=0.5, alpha=0.01):
        super(GradLockFC, self).__init__()
        self.fc = nn.Linear(in_features, out_features, bias=True)
        self.injection_ratio = injection_ratio
        self.alpha = alpha
        
        # Calculate stateless deterministic indices (Equation 1)
        self.n_row = out_features
        num_vaults = int(self.injection_ratio * self.n_row)
        i_indices = np.arange(num_vaults)
        selected_rows = np.floor(
            self.n_row * np.abs(np.sin(np.pi * i_indices / (self.n_row / self.injection_ratio)))
        ).astype(np.int64)
        self.selected_rows = np.unique(selected_rows) # Resolve any potential collisions
        
        # Construct the binary gradient mask (M)
        self.mask = torch.zeros_like(self.fc.weight.data)
        self.mask[self.selected_rows, :] = 1.0
        
        # Register the backward hook to enforce gradient locking (Equation 2)
        self.fc.weight.register_hook(self.create_grad_hook())
        
    def inject_payload(self, private_samples):
        """
        Injects normalized and scaled training images directly into target weights.
        """
        with torch.no_grad():
            for idx, row in enumerate(self.selected_rows):
                if idx >= len(private_samples):
                    break
                # Flatten, normalize to [-1, 1], and scale
                flat_sample = private_samples[idx].flatten()
                normalized = (flat_sample - flat_sample.min()) / (flat_sample.max() - flat_sample.min() + 1e-8)
                normalized = (normalized * 2.0) - 1.0
                
                # Truncate or pad to match input features
                payload = torch.zeros(self.fc.weight.data.shape[1], device=self.fc.weight.device)
                size_to_copy = min(len(normalized), len(payload))
                payload[:size_to_copy] = normalized[:size_to_copy]
                
                # Write to the parameter tensor (Equation 4)
                self.fc.weight.data[row, :] = self.alpha * payload

    def create_grad_hook(self):
        # Capture mask in the closure to modify gradients dynamically
        mask = self.mask.clone().to(torch.device("cuda" if torch.cuda.is_available() else "cpu"))
        def hook(grad):
            return grad * (1.0 - mask)
        return hook

    def forward(self, x):
        return self.fc(x)
```

## Experimental Results

The authors evaluated GradLock against three post-training Model Inversion (MI) attacks—Generative Model Inversion (GMI) [32], Knowledge-Enriched Distributional Model Inversion (KEDMI) [5], and Pseudo-Private Data Guided (PPDG) [20]—as well as the training-time Least Significant Bit (LSB) Parameter Encoding baseline [25]. Experiments were conducted on MNIST, Imagenette, and CelebA datasets using convolutional and Transformer architectures.

### Visual Fidelity & Reconstruction Accuracy
The baseline LSB Encoding method and GradLock both achieve mathematically perfect reconstruction under ideal, post-training settings (SSIM of 1.000, LPIPS of 0.000, and KNN distances under 0.02 across VGGNet-16, ResNet-18, and DenseNet-121). However, the critical divergence occurs when the models undergo standard post-training optimization pipelines.

### Robustness Against Model Optimizations
Standard post-processing steps act as "unintentional sanitizers" for naive parameter injections. When subjected to standard LSB filtering, INT8 quantization, weight pruning (30%), or transfer learning fine-tuning, the LSB Encoding baseline suffers from catastrophic failure; weight perturbations completely corrupt the bit-level serialization, rendering recovery impossible. 

In contrast, GradLock demonstrates strong structural resilience, preserving low-frequency, highly recognizable semantic structures (such as facial contours, shapes, and digits) across all post-processing environments:
- **LSB Filtering**: The visual quality of the extracted data remains virtually indistinguishable from the original injection, leaving GradLock unaffected.
- **Quantization**: Despite the reduction in numerical precision from 8-bit integer (INT8) quantization, the core semantic features of the objects remain intact.
- **Weight Pruning**: Removing 30% of the model parameters via magnitude-based pruning results in partial color loss, but structural outlines and key landmarks are successfully preserved.
- **Fine-Tuning**: After fine-tuning the pruned model for 20 epochs to simulate transfer learning, the underlying identity features remain recognizable despite the introduced noise.

### Time Complexity Comparison
Post-training MI approaches require computationally intensive iterative optimization through external generators. For instance, PPDG takes 48,423.59 seconds (approximately 13.4 hours) to reconstruct a single batch of CelebA faces from a ResNet-18 model. GradLock, by directly querying targeted indices and applying the scaling inverse, achieves reconstruction in **0.29 seconds** on ResNet-18—representing a $1.6 \times 10^5 \times$ speedup (Table 8). Across all evaluated architectures, GradLock achieves an average extraction latency of 0.377 seconds, representing instant extraction (< 1.0s).

### User Deployment Study
To evaluate practical feasibility, the authors conducted a blind deployment study involving 30 software engineering participants tasked with training a facial recognition classifier. 
- **93.3%** of the participants integrated and executed the compromised training code (containing the malicious `initialize()` helper inside `utils.py`) without performing any inspection or raising security concerns, submitting the trained model.
- Only **16.7%** of participants attempted any form of code review.
- Only **3.3%** (a single participant) successfully flagged the anomalous gradient-masking logic, and this was achieved solely through reliance on an automated, LLM-based code auditing tool rather than manual inspection.

## Limitations & Open Questions

Despite the high persistence and visual fidelity of the GradLock attack, several structural bottlenecks remain:

1. **Permutation Defenses**: Because GradLock relies on deterministic indexing ($r_i$) mapped to specific coordinates in the final layer's weight matrix, any post-training optimization that applies channel shuffling or structural weight permutation (without altering the layer's mathematical output) could disrupt the location mapping, rendering the retrieved data useless.
2. **Capacity Bottlenecks**: The attack is mathematically constrained by the dimensionality of the classification layer. To prevent task accuracy degradation, the authors limit injection to $\le 60\%$ of the final layer parameters. For a standard ResNet-18 model with a 1,000-class output, this limits total exfiltration capacity to approximately 146 images (at $64 \times 64$ resolution). It cannot be used to silently exfiltrate massive, multi-gigabyte training sets.
3. **Requirement of Code Execution**: The threat model assumes the adversary has write-access to the training environment (i.e., via dependency confusion or compromised open-source libraries). If the training pipeline is strictly controlled and verified, the attack cannot execute.

## What Practitioners Should Do

Security engineers and ML platform architects should take immediate, concrete steps to secure their pipelines against training-time parameter exfiltration:

### 1. Enforce Runtime Gradient Inspection
Monitor the variance of parameter updates during training. Because GradLock relies on forcing specific gradients to zero via hooks, you can flag models showing abnormal, static gradient paths.
- **Action**: Implement automated training checks that monitor the sparsity of the gradient tensor. Flag any training runs where a non-zero parameter consistently returns a gradient update of exactly `0.0` over multiple epochs.

### 2. Implement Post-Training Parameter Permutation
Neutralize deterministic coordinate mapping by permuting the channels of fully connected and convolutional layers prior to public release.
- **Action**: Write a sanitization script that shuffles the rows of weight matrices in the classification heads and updates the corresponding incoming connection layers to preserve functional outputs while scrambling coordinate-based data vaults.

### 3. Conduct Strict Auditing of PyTorch Backpropagation Hooks
The most critical vector of this attack is the dynamic registration of backward hooks. Standard static analysis tools often miss these because they are masked as standard initialization functions.
- **Action**: Add static analysis rules (e.g., via Semgrep) to intercept any calls to `register_hook` or custom backward routines within codebases pulled from external registries:

```yaml
rules:
  - id: detect-custom-gradient-hooks
    pattern: $PARAMETER.register_hook(...)
    message: "Detected manual registration of gradient backpropagation hooks. This must be audited for potential gradient-masking and data exfiltration vectors."
    severity: WARNING
    languages: [python]
```

### 4. Lock Down Upstream Machine Learning Dependencies
Prevent the initial compromise of training environments by enforcing strict provenance and supply chain controls.
- **Action**: Ensure all dependencies in `requirements.txt` or `pyproject.toml` are locked with cryptographic hashes using tools like Pipenv or Poetry. Utilize private package mirrors that scan incoming third-party packages for typosquatting and dependency confusion vulnerabilities.

## The Takeaway

Neural network parameters can no longer be evaluated solely as passive statistical representations of a target task; they must be audited as highly structured, active files capable of carrying stealthy and highly persistent data payloads. By shifting the manipulation vector from static, post-training bit modification to active, training-time gradient locking, frameworks like GradLock demonstrate that a compromised supply chain can successfully exfiltrate sensitive training data even through highly restrictive environments like isolated Data Clean Rooms. Until ML platform security incorporates rigorous gradient auditing and parameter randomization, the public sharing of trained weights remains a viable privacy leakage vector.

## Den's Take

Weight-based exfiltration is a fascinating threat vector, but framing GradLock’s stealth solely around developer oversight in code reviews misses the real battleground. While I appreciate the authors proving that 93.3% of their user study participants missed the malicious PyTorch optimization logic, code inspection is a notoriously weak line of defense for ML pipelines. The real flaw of GradLock is its dynamic signature during training. Freezing specific parameter coordinates via gradient masking creates a highly anomalous artifact: absolute zero-variance gradients at identical coordinates across multiple epochs.

This highlights the danger of upstream supply chain dependencies being weaponized to bypass runtime checks entirely, turning static weights into an offline exfiltration vault.

My prediction is that as secure Data Clean Rooms become standard, the focus will shift from static code analysis to runtime telemetry profiling. If a training pipeline shows zero-gradient update patterns on specific coordinates in the final classification layers, security orchestrators will easily flag it. Relying on developers to catch stealthy initialization code is a losing game, but monitoring gradient distribution anomalies during training is highly achievable.
