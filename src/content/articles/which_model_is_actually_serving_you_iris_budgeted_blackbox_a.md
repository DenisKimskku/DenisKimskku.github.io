# Auditing LLM Gateways: How IRIS Detects Silent Model Substitution and Routing Dilution From Visible Strings

The proliferation of secondary API brokers and cost-optimized LLM routers has introduced a silent threat to modern AI pipelines: the quiet downgrading of models by intermediary gateways looking to arbitrage inference costs. When an enterprise LLM pipeline or an agent querying a high-tier model is secretly routed to a cheaper, quantized, or smaller model, performance drops silently while billing remains unchanged. To address this mismatch, researchers have developed IRIS (Information-Rate Inspection from Strings), a black-box auditing framework that detects both wholesale model substitution and fractional "routing dilution" using only the raw text returned from random-generation challenges.

## Threat Model

| | |
|---|---|
| **Attacker** | A cost-minimizing or malicious API gateway or shadow API reseller. |
| **Victim** | LLM API clients and enterprise pipelines paying for premium nominal models (e.g., Qwen3-32B or Llama-3.3-70B). |
| **Goal** | Quietly substitute the requested nominal model $P$ with a cheaper model $R$ on either 100% of queries (substitution, $\epsilon = 1$) or a fraction of queries (routing dilution, $\epsilon \in (0, 1)$) to pocket the profit margin. |
| **Budget** | Strictly black-box, text-only access. The auditor cannot access log-probabilities, token ranks, or internal model weights, and must pay standard per-token rates for verification queries. |

## Background and Problem Setup

To set up a rigorous comparison, let's look at how prior black-box verification tools operate. Most output-only methods are limited to returning binary verdicts on fixed budgets and struggle to address the fractional dilution of API streams.

### Table 1: Black-Box Auditing Methods Comparison

| Method | Access Signal | Probes | Detection Capabilities | Budget Strategy |
| :--- | :--- | :--- | :--- | :--- |
| **IRIS** | Raw Text Only | Reusable `rand-gen` (random generation) | Whole-stream substitution, fractional dilution, attribution, $\epsilon$ estimation | Self-estimated before audit ($m^{\star}$) |
| **FLIPS** (Richardeau et al. 2026) | Raw Text Only | Reusable `rand-gen` | Instance identification, whole-stream substitution | Fixed by design |

| **KBF** (Fang et al. 2026) | Raw Text Only | Model-specific knowledge boundaries | Substitution, dilution estimation (only for known substitutes under fixed routing) | Fixed by design |

Unlike MET, which relies on a massive collection of reference samples, or RUT, which requires accessing the log-ranks of output tokens, IRIS operates purely on returned text. IRIS addresses the query-budget blind spot: rather than forcing the auditor to run a fixed query budget that might be too small to detect subtle dilution or wasteful on obvious substitutions, IRIS uses a cheap pilot phase to fit the exponential rank-error decay and size its own query budget $m^{\star}$ before the actual audit begins.

## Methodology

The implementation of the IRIS framework consists of two core phases: **Audit-Plan Construction** and **Audit Execution**.

### 1. Probe Design and Random Generation Challenges
To expose backend-specific sampling biases without relying on easily memorized factual knowledge probes, IRIS uses a suite of task-agnostic random generation probes. For instance, probe $c_{2,16}$ asks the model:

```text
Generate exactly 16 symbols by independently choosing uniformly between 0 and 1. 
Output the sequence only, with no spaces and no explanation.
```

Because LLM samplers struggle to produce perfectly uniform random strings due to underlying vocabulary biases and temperature-scaling quirks, these outputs act as a model-specific fingerprint.

### 2. Feature Extraction and Classification
For a given response $y$, IRIS extracts a 179-dimensional feature vector $\phi(y)$ (detailed in Table 21 of the paper). These features include:
- Symbol frequencies (e.g., `freq_0`, `freq_1` through `freq_9`)
- Autocorrelation metrics (`autocorr_lag1`, `autocorr_lag2`)
- Entropy measures (`entropy_norm`)
- Formatting compliance flags (`exact_len`, `contains_space`)

A multiclass classifier $g_c$ (implemented as a 300-tree random forest) is trained on labeled historical outputs from the nominal model $P$ and candidate substitutes $\{R_1, \dots, R_J\}$. The deployed anomaly score is the negative log-posterior of the reference model:

$$s_c(y) = -\log \hat{\mathbb{P}}_c(P \mid y)$$

An average score over $m$ queries forms the episode-level evidence statistic:

$$S_m(c) = \frac{1}{m} \sum_{i=1}^m s_c(y_i)$$

### 3. Budget Optimization: The Estimate-then-Budget Strategy
In Stage I, IRIS runs a cheap pilot (using $m \le 4$ queries) to fit an exponential decay on the Area Under the Receiver Operating Characteristic (AUROC) curve (Eq. 6):

$$\log(1 - \text{AUROC}_{cj}(m)) \approx \hat{a}_{cj} - \hat{I}_{\text{auc},cj} m$$

Using a one-sided $t$-based lower bound on the decay exponent $I_{\text{auc},cj}$, IRIS calculates the exact query budget $m_{\text{sub}}$ required to meet a target rank-error threshold $\delta$ (Eq. 7):

$$m_{\text{sub}}(c) = \max_{j \in \mathcal{J}_{\text{audit}}} \left\lceil \frac{a_{cj} - \log \delta_{\text{auc}}}{I_{\text{auc},cj}} \right\rceil$$

For fractional dilution audits, a threshold $\tau$ converts each score into a binary "tell" (an atypical response where $s_c(y) > \tau$). The budget $m_{\text{dil}}$ is optimized over a grid of candidate thresholds to ensure that the detection power meets a target $1 - \delta$ under a specified minimum dilution rate $\epsilon_{\text{min}}$ (Eq. 12).

### Analysis of Metrics
While IRIS claims a substantial victory over MET and RUT (MET-MMD is mathematically degenerate at $m=1$ with an AUROC of $0.111$, and RUT's rank uniformity stays weak on dilution with a maximum AUROC of $0.631$ at $m=32$), its performance compared to FLIPS on basic substitution is virtually identical. At $m=8$, FLIPS edges out IRIS slightly in both substitution AUROC ($0.9999$ vs $0.9997$) and attribution accuracy ($0.999$ vs $0.998$). 

The primary differentiator of IRIS is structural: it is the only framework capable of handling fractional routing dilution and estimating the dilution parameter $\hat{\epsilon}$ with a mean error of only $0.04$ (Table 1), whereas FLIPS lacks any mechanism to audit diluted streams.

### Gateway Evaluation at Scale (OpenRouter)
When deployed across 17 real-world commercial OpenRouter models (Section 6.2):
- IRIS detects $\epsilon = 0.3$ dilution on 218 of the 272 margin-qualified pairs at a mean power of $0.85$ (with an empirical false-positive rate of $0.017$).
- However, 54 of the 272 pairs ($19.8\%$) are marked as "low-margin/indeterminate" (e.g., within Qwen3 8B/32B, or GPT-4.1 vs GPT-4o-mini). For these close relatives, the sampling distributions are too similar to reliably detect low-rate dilution within reasonable query budgets ($m=80$).
- When encountering an *unseen* (unenrolled) diluent, the "leave-one-out" validation shows that detection power degrades only marginally (dropping from $0.85$ to $0.78$ at $\epsilon = 0.3$), turning the estimation $\hat{\epsilon}$ into a strict lower bound.

## Limitations and Open Questions

A critical examination of the IRIS framework reveals several production challenges:

- **Low-Margin Indeterminacy**: IRIS struggles with "close relatives" (e.g., same model family under minor architectural changes or parent-child models like GPT-4.1 and GPT-4o-mini). Section 6.2 acknowledges that 54 of 272 pairs are indeterminate because their random generation distributions overlap heavily.
- **Evasion and Adaptive Routers**: While Section S12 (Paraphrase Robustness) notes that IRIS's random-generation prompts are robust to basic word-level rephrasing (retaining an attribution accuracy of 0.99 to 1.00 at $m=8$), a fully adaptive gateway that semantically parses the prompt could identify random-generation challenges and serve them honestly using the nominal model while diluting normal user queries.
- **Temperature Retuning Sensitivity**: Although the authors prove in Section S25 that temperature changes are "second-order" effects requiring substantially larger budgets ($m = \Theta((\Delta\beta)^{-2})$) to resolve compared to base model swaps ($m = \Theta(1)$), a sophisticated attacker could mix slight temperature drops with model changes to distort the statistical fingerprint.
- **High Sample Intensity for Certified Bounds**: Realizing strict type-I error control ($\alpha_1 \le \alpha/m$) on a deep tail requires thousands of reference samples during calibration (Section S4), meaning that true "on-demand" auditing without pre-enrolled databases is impractical.

## What Practitioners Should Do

### 1. Deploy Pre-Warm Probes with Fixed Seeds
Implement a background job that periodically sends the primary sequence probes ($c_{2,16}$ and $c_{10,8}$) to your nominal endpoints to maintain a fresh baseline of sampling distributions. Use standard OpenAI-compatible API configurations: set `temperature=1.0` and `top_p=1.0` to maximize entropy, and explicitly disable reasoning/thinking tokens (e.g., `{"effort": "low"}` or `{"enabled": false}`).

### 2. Implement Task-Embedded Probe Prefixes
To defeat adaptive gateways that selectively route obvious random-generation prompts honestly, embed the probe directly inside standard production queries. Prepend or append an instruction requiring the response to begin with a short random string before answering the substantive prompt:

```text
Before answering the user query, output exactly 16 binary symbols 
(0s and 1s) with no spaces or explanation.

User Query: [Insert production task prompt here]
```

Parse the prefix characters for the 179-dimensional feature dictionary before passing the rest of the response to your downstream application.

### 3. Establish a Low-Margin Exclusion Zone
Prior to auditing, run a cheap pilot split ($m \le 4$) to estimate the pairwise tail exponent $\kappa$. If the pair exhibits a near-greedy wall ($\kappa \to 1$ as seen in Table 22), classify the pair as non-identifiable and do not waste query budget attempting to verify dilution rates.

### 4. Audit Cross-Provider Pairs
When procuring open-weight models (e.g., Llama-3.3-70B or DeepSeek-Chat) from multiple API resellers, do not assume identical distributions. Perform two-sample Kolmogorov-Smirnov or Mann-Whitney U tests on the extracted visible-string features (like `autocorr_lag1` or `entropy_norm`) to flag stealth quantization (e.g., FP8 vs BF16) or kernel-level deviations.

## The Takeaway

IRIS demonstrates that the subtle sampling biases inherent to LLM architectures cannot be completely masked by API gateways, providing a text-only auditing mechanism to enforce Service Level Agreement (SLA) compliance. By transforming the query budget from a fixed hyperparameter into an actively estimated object, the framework makes black-box verification financially viable. Ultimately, the research exposes a fundamental truth: as long as gateways must return raw text, their cost-saving compromises will remain statistically readable.

---

## Den's Take

While IRIS offers an elegant mathematical framework for estimating query budgets, its reliance on "rand-gen" (random-generation) challenges exposes a massive operational vulnerability. A malicious API gateway executing arbitrage is unlikely to be a passive observer. Because random-generation prompts have highly distinct statistical signatures—exhibiting atypical token distributions compared to normal enterprise queries—any competent adversary can easily build a simple input classifier to detect them. Once flagged, the gateway can simply route those specific audit queries to the genuine premium model while continuing to dilute standard traffic. 

This threat of active evasion makes the paper's self-optimized budget of 80 queries for detecting a dilution rate of $\epsilon = 0.3$ somewhat academic. As I noted when reviewing other AI watermark and fingerprinting frameworks, static forensic markers are notoriously easy to circumvent once an adversary actively adapts to the detection mechanism. If the gateway operator knows you are probing with rand-gen sequences, they will selectively behave themselves on those exact inputs. For IRIS to be practically viable in production pipelines, we need auditing challenges that are indistinguishable from normal, semantic user queries, rather than obvious synthetic probes.
