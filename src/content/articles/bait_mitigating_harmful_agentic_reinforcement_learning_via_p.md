# Bait: Probing Reward Functions to Mitigate Harmful Agentic Reinforcement Learning

## TLDR
*   **What**: Bait probes the reward function to detect malicious tuning.
*   **Who's at risk**: LLMs deployed via agentic RL-as-a-service APIs.
*   **Key number**: N/A

## The Agentic RL Misalignment Gap
Agentic Reinforcement Learning (RL)-as-a-service allows users to customize a large language model by providing a user-specific environment, which includes agentic instructions and a reward function. The service provider optimizes the model based on these user-provided feedback signals. The vulnerability lies in the fact that users can deploy a "toxic environment"—specifically, a harmful reward function—to steer the model away from its initial safety alignment. This allows an attacker to destroy safety alignment with minimal cost, such as \$20. Once degraded, the model can be used for harmful activities, like exploiting software vulnerabilities and launching code re-use attacks. Prior work showed that on-policy RL with a wrong reward signal can subvert safety alignment. However, the challenge is detecting this malicious signal when the environment is entirely controlled by the user.

## Reward Divergence as a Detection Criterion
Bait introduces a proactive mechanism to detect if a harmful reward function is active in the user environment. The core insight is that if the reward function is toxic, it will disproportionately reward explicitly harmful content. Bait addresses this by injecting "Bait responses"—explicitly harmful responses generated by a separate Bait model—into the standard RL rollout group alongside the policy model's responses. The system then measures the difference in reward assigned to these injected Bait responses versus the standard policy responses. This difference is quantified by the reward divergence, $\delta$. If $\delta \geq 0$, the system flags the reward function as likely harmful because the attacker's function prefers the explicit harmful Bait content over the policy's output.

## Policy Optimization Loss Adjustment
The mechanism operates by modifying the RL cycle's reward rating stage. When the reward divergence $\delta$ is positive (indicating a harmful reward function), the defender intervenes by reversing the reward value to apply a penalty during the policy optimization. This penalty is applied to suppress the model from learning from the malicious feedback. The process starts by randomly replacing $\epsilon$ responses in the group of $G$ responses with Bait responses $\{\tilde{a}_i\}_{i \in [\epsilon]}$. The environment then returns rewards $\{r_i\}_{i \in [G]}$. The detection is made by calculating:

$$\delta = \text{mean}(\{r_i\}_{i \in [\epsilon]}) - \text{mean}(\{r_i\}_{i \in [G] \setminus [\epsilon]})$$

If $\delta \geq 0$, the penalty is applied to the loss function, preventing the policy from optimizing towards the harmful signal. This defense successfully mitigates learning from a harmful reward function while maintaining the ability to learn from a benign one. An adaptive attack, Excision, attempts to bypass this by masking the top-K rewards to 0, but this attack fails due to "mis-excision," which causes the reward divergence to remain positive.

## Limitations
The threat model is scoped specifically to the agentic-RL-as-a-service scenario; generalization to models trained outside this API structure is not proven. Furthermore, the defense relies on the assumption that the Bait model can reliably generate responses that the harmful reward function will rate highly. If the attacker can manipulate the reward function to ignore or penalize the Bait responses themselves, the detection mechanism could fail.

## What practitioners should do
*   Implement a proactive probing step before customizing models via RL APIs.
*   Monitor for a positive reward divergence statistic ($\delta \geq 0$) during agentic RL training cycles.
*   If positive divergence is detected, apply a penalty to the policy optimization loss to counteract harmful reward signals.
*   Be aware that adaptive attackers can attempt to manipulate reward signals, though Bait shows resilience against the tested Excision technique.

## Verdict
Read this paper if you are building or securing agentic RL services; otherwise, skip it.

## Den's Take

The paper presents a functional approach to detecting reward function manipulation in agentic RL services, which is a necessary step given the risks of user-controlled toxicity. However, the reliance on the Bait model to reliably generate signals that the attacker's function *must* rate highly is a significant, unaddressed assumption. If the attacker can tune their reward function to ignore or treat the explicit harmful content generated by Bait as noise—rather than a high-reward signal—the entire divergence check collapses. Furthermore, the defense only addresses the reward *rating* stage; it does little to prevent the capability degradation that occurs *before* the reward function is even applied, which is a more fundamental system integrity issue.
