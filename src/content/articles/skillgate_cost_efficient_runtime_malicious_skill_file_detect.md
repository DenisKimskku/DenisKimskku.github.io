## TLDR
- **What**: SKILLGATE is a hybrid security gateway that uses a 530-pattern regex prefilter and a targeted LLM-judge snippet window to detect malicious Markdown "skill" files at runtime.
- **Who's at risk**: Enterprise software engineering teams deploying autonomous AI coding agents (such as Claude Code, Cursor, and GitHub Copilot) that consume third-party skill files or integrate with the Model Context Protocol (MCP).
- **Key number**: SKILLGATE reduces LLM input tokens by 76.9% compared to full-file screening, achieving an F1-score of 0.817 and a false positive rate (FPR) of 1.13% on the SkillsBench dataset.

---

Autonomous AI coding agents, such as Cursor, Claude Code, and GitHub Copilot, operate with elevated access on developer workstations, frequently executing shell commands, reading files, and writing code with minimal user intervention. To customize agent behavior, teams are adopting discipline-specific "skill files"—plain Markdown documents delivered via the Model Context Protocol (MCP). This paper introduces SKILLGATE, a deployable security gateway designed to intercept, analyze, and block malicious skill files before they can hijack agent contexts and compromise developer endpoints.

| | |
|---|---|
| **Attacker** | Non-adaptive adversary controlling skill file contents in a public registry (e.g., ClawHub) or Git repository, without explicit knowledge of deployed defensive rulesets. |
| **Victim** | Software developers and enterprise environments utilizing autonomous AI coding agents (e.g., Claude Code, Cursor, GitHub Copilot). |
| **Goal** | Achieve arbitrary code execution, credential exfiltration (e.g., `~/.aws/credentials`, `~/.ssh/id_rsa`), or backend API redirection via malicious instructions embedded in Markdown skill files. |
| **Budget** | Negligible; requires only publishing malicious Markdown skill packages to public registries using commands like `npx skills add`. |

## Background / Problem Setup

AI skill files are typically delivered via public registries or loaded dynamically at runtime through the MCP interface via three response types: `tools/call`, `resources/read`, and `prompts/get`. Because these skill files are structured as plain Markdown rather than executable code, they bypass traditional software composition analysis (SCA) and static analysis tools.

| Tool / Method | Detection Target | Mechanism | Primary Limitation |
|---|---|---|---|
| **SCA / Static Scanners** (e.g., Semgrep [11], Snyk [12]) | Executable source code | Abstract Syntax Tree (AST) & pattern matching | Cannot parse or evaluate natural-language behavioral instructions in Markdown. |
| **ClawVet** [34] | MCP skill files | 54 hard-coded regex patterns in 6 passes | Extremely high false positive rate (50.40% FPR on SkillsBench), rendering it undeployable in production. |
| **SkillScanner** [35] | MCP skill files | YARA/regex + behavioral control-flow graph | High false positive rate (17.40% FPR); optional full-file LLM judge is cost-prohibitive and slow. |
| **SKILLGATE** (Proposed) | MCP skill files & commands | 530-pattern regex prefilter + targeted LLM snippet judge | Relies on external API endpoints (`gpt-5.4-mini`); potential bypass via advanced obfuscation. |

As the paper describes, the fundamental tension in skill-file security lies between the high false positive rates of pure pattern matching and the extreme token costs and latency of evaluating every file with a full Large Language Model (LLM) scan.

## Methodology

SKILLGATE is designed as a local daemon proxy that intercepts skill installations and MCP calls. It implements a multi-stage pipeline as illustrated in Figure 2:

```
[Skill Files / Install Commands]
              │
              ▼
    ┌──────────────────┐
    │ 1. Runtime Proxy │
    └─────────┬────────┘
              │
              ▼
    ┌──────────────────┐      No (Zero Hits)
    │2. Regex Prefilter├──────────────────────┐
    └─────────┬────────┘                      │
              │ Yes (Pattern Matched)         │
              ▼                               ▼
    ┌──────────────────┐             ┌─────────────────┐
    │3. Snippet Extract│             │   Safe Install  │
    └─────────┬────────┘             └─────────────────┘
              │                               ▲
              ▼                               │
    ┌──────────────────┐             ┌────────┴────────┐
    │  4. LLM Judge    ├────────────►│  Policy Engine  │
    └──────────────────┘  Safe       └────────┬────────┘
                                              │ Block / Quarantine
                                              ▼
                                     ┌─────────────────┐
                                     │     Blocked     │
                                     └─────────────────┘
```

### Stage 1: Runtime Proxy & Content Extraction
SKILLGATE runs as a Unix-socket daemon (`~/.skillgate/skillgate.sock`) acting as a transparent proxy between the coding agent and any upstream MCP server. It intercepts `tools/call`, `resources/read`, and `prompts/get` payloads.

### Stage 2: Regex Prefilter
The payload is evaluated by a `RuleEngine` compiling 530 patterns (428 patterns systematically derived from the MITRE ATT&CK framework [15] and 102 imported from the Sigma detection format [16]). If a file generates zero hits, it bypasses the LLM judge entirely (referred to as **skip savings**), processing at near-zero cost. Table I lists representative prefilter patterns used:

| ID | Technique | Category | Pattern (simplified) | Severity |
|---|---|---|---|---|
| RCE010 | T1140 | Def. Evasion | `base64 -d \| sh` | CRIT |
| CRED010 | T1552.001 | Cred. Access | `.aws/credentials` | CRIT |
| EXFIL002 | T1048 | Exfiltration | `curl --data @/<path>` | HIGH |
| PERS002 | T1546.004 | Persistence | `>> .bashrc` | HIGH |

### Stage 3: Snippet Extraction & LLM Judge
For files triggering at least one pattern, a `ContentExtractor` builds a window around each hit, taking a character window (`cw`) of 500 characters by default. Overlapping windows are deduplicated, and up to `ms=20` windows are concatenated. This subset (the **snippet savings**) is sent to the LLM judge (`gpt-5.4-mini`) instead of the entire file.

### Stage 4: Policy Engine & Audit Log
The LLM returns a classification (`SAFE`, `SUSPICIOUS`, or `MALICIOUS`) with a confidence score. The `PolicyEngine` maps this to concrete actions:
- `MALICIOUS` (confidence $\ge 0.7$) $\rightarrow$ **BLOCK**
- `SUSPICIOUS` (confidence $\ge 0.5$) $\rightarrow$ **QUARANTINE** (written to `~/.skillgate/quarantine/` for audit)
- `SUSPICIOUS` (confidence $< 0.5$) $\rightarrow$ **WARN**
- `SAFE` $\rightarrow$ **ALLOW**

All lifecycle steps are appended to `~/.skillgate/logs/audit.jsonl`.

### Skills CLI Gate
SKILLGATE also ships a PATH shim (`skillgate install-skills-shim`) that transparently routes any `npx skills add <package>` command through the gateway.

## Limitations & Open Questions

While SKILLGATE represents a major upgrade over static-only pattern matchers, practitioners should maintain a healthy skepticism regarding several design parameters:

1. **Assumptions on Adversarial Adaptability**: The paper models a *non-adaptive* adversary. If an attacker has white-box or gray-box access to the 530 compiled regex patterns, they could restructure payloads (e.g., breaking up exfiltration scripts with natural language or utilizing advanced instruction fragmentation) to prevent prefilter matching. Because a prefilter miss completely bypasses the LLM judge, this would result in a silent failure.
2. **False Positive Dominance**: Figure 4 details the categorization of SKILLGATE's 17 false positives on SkillsBench. The majority (71% / 12 files) are triggered by benign Base64-encoded segments embedded in markdown documentation. This suggests the tool struggles to differentiate between benign sample payloads and actual execution payloads.
3. **Non-Determinism of LLM Judges**: Because the final verdict rests on `gpt-5.4-mini`, the tool exhibits minor run-to-run variance (an F1 standard deviation of 0.013 over three runs). In high-availability DevOps pipelines, non-deterministic gating can lead to flaky build steps.
4. **Local LLM Performance**: The paper notes that local backends (e.g., using Ollama) were not evaluated. Evaluating local models is a necessity for air-gapped enterprise networks where transmitting snippets to external APIs is restricted.

## What Practitioners Should Do

If you are deploying autonomous coding agents or integrating MCP servers inside your organization, implement these active guardrails:

### 1. Route MCP traffic through a transparent local proxy
Configure your coding agent's MCP configurations (such as `cursor.config` or your Claude Code integration file) to route through a Unix socket proxy rather than direct standard I/O pipes. Ensure that any dynamic skill payload delivered via `resources/read` is inspected.

### 2. Implement the PATH Shim for Install-Time Shimming
Deploy the SKILLGATE shim to intercept development-level package managers. This intercepts external commands and blocks untrusted third-party Markdown files before local directories ingest them:

```bash
# Install the skills shim in the developer shell environment
skillgate install-skills-shim

# Verification: Any standard addition is now intercepted
npx skills add clawhavoc-theme
```

### 3. Implement a Tiered Quarantine Policy
Avoid a binary block/allow policy. Instead, configure a middle tier in your deployment configurations to write high-risk flagged files with borderline confidence scores ($0.5 \le \text{confidence} < 0.7$) to a quarantine path for manual security analyst sign-off:

```json
{
  "policy": {
    "malicious_threshold": 0.7,
    "quarantine_threshold": 0.5,
    "quarantine_path": "~/.skillgate/quarantine/"
  }
}
```

### 4. Feed Audit Logs to SIEM Pipelines
Ingest the structured audit output (`~/.skillgate/logs/audit.jsonl`) into your centralized Security Information and Event Management (SIEM) pipeline. This provides visibility into any attempted prompt injection or exfiltration signatures occurring at the developer context window level.

## The Takeaway

Securing AI coding agents requires specialized runtime intervention at the instruction ingestion layer, as traditional static scanners are blind to behavioral manipulation in Markdown. Purely static pattern matching produces too many false alarms, whereas complete LLM file scans are too slow and expensive for everyday development. By combining MITRE-derived regex patterns with targeted LLM snippet analysis, pipelines like SKILLGATE show that runtime protection for agent workspaces can be both accurate and cost-effective.

## Den's Take

Assuming a "non-adaptive adversary" in the threat model is a glaring shortcut that undermines SKILLGATE's real-world viability. While the 76.9% reduction in input tokens sounds impressive on paper, this economic efficiency is an illusion once attackers realize they are up against a 530-pattern regex prefilter. Because Markdown-based instructions lack strict AST constraints, an attacker can bypass these regex rules using basic prompt obfuscation—such as indirect injection, split-instruction payloads, or homoglyph substitution—without breaking the semantic meaning parsed by the agent. Once the regex is bypassed, the downstream LLM-judge either misses the threat entirely or is forced to digest much larger context windows to catch adaptive exploits, destroying the claimed cost savings.

This reliance on content-level inspection highlights a broader architectural issue in agent security. As I have argued previously regarding declarative tool-use security, trying to secure agent-tool interactions by filtering natural language is fundamentally less robust than enforcing declarative, zero-trust execution boundaries at the runtime level. Instead of trying to pre-screen every markdown skill file, engineering teams should sandbox the MCP server process itself, strictly limiting its filesystem access and network egress. If your security posture depends on a regex prefilter successfully flagging a clever prompt injection, you have already lost.
