# Decision-Level Hijacking: Manipulating LLM Cognitive Stance via Targeted Post-Deployment DRAM Bit-Flips

Security boundaries for deep learning systems traditionally focus on software-level vectors, such as adversarial prompt injections or training-phase data poisoning. However, the physical memory infrastructure where model weights reside during inference represents an unshielded, low-level attack surface. 

This post analyzes a paper introducing "Decision-Level Hijacking," a paradigm demonstrating that an attacker can systematically manipulate a model's cognitive stance on specific topics through targeted hardware memory tampering. By leveraging Rowhammer-style physical memory fault injection, the authors' proposed CogBias framework breaks the long-held assumption that physical weight-integrity threats only manifest as total system collapse or generic performance degradation. Instead, threat actors can covertly guide the outputs of autonomous enterprise agents, such as procurement bots or market analysis tools, to favor specific commercial brands or ideological stances without leaving any detectable traces in the model's training data, prompt inputs, or baseline metrics.

## Technical Deep-Dive

The technical core of CogBias lies in solving a fundamental optimization problem: how do we locate a tiny set of discrete bits whose modification shifts the model's high-level cognitive stance on specific topics without altering its performance on general tasks?

Because discrete token selection and bit manipulation are non-differentiable, CogBias constructs a continuous, differentiable proxy of the attack pipeline and uses gradient-based sensitivity analysis paired with a Genetic Algorithm (GA) to pinpoint the target bits.

```
+------------------+     +--------------------------+     +---------------------------+
| Hijacked LLM with| <-- |   Bit-Flip Execution     | <-- |   BitScout Search (GA)    |
| Cognitive Bias   |     |    (Rowhammer/BitHydra)  |     |   Gradient + Combinatorics|
+------------------+     +--------------------------+     +---------------------------+
```

### 1. Differentiable Sentiment Projection (DSP)
To bypass the non-differentiable step of autoregressive token generation, CogBias relaxes the hard token selection using a temperature-controlled Softmax over the target model's output logits $z_t \in \mathbb{R}^{|V|}$ at step $t$:

$$p_t = \text{Softmax}(z_t / \tau) \in \mathbb{R}^{|V|}$$

A soft word embedding sequence $\tilde{V} = [\tilde{v}_1, \dots, \tilde{v}_T]$ is then constructed using the word embedding matrix $E_p \in \mathbb{R}^{|V| \times d}$ of a secondary sentiment classifier:

$$\tilde{v}_t = \sum_{i=1}^{|V|} p_{t, i} \cdot E_p[i] \in \mathbb{R}^d$$

This soft sequence passes gradient information backwards to the model parameters $\theta$ while avoiding the gradient truncation caused by discrete sampling. To prevent gradients from dispersing across background words, CogBias detects the token positions $p(e)$ of the target entity $e$ and applies a Gaussian context-weighting mask vector $\omega$:

$$\omega_t = \max_{j \in p(e)} \exp\left( - \frac{(t - j)^2}{2\sigma^2} \right)$$

$$\tilde{V}_{\text{mask}} = \omega \odot \tilde{V}$$

This masked representation is fed into a lightweight sentiment classifier $f_\phi$ (such as a fine-tuned DistilBERT or a specialized domain classifier like `climate-attitude-LM`), yielding a continuous sentiment polarity score $\Phi(x, e, \theta) \in [-1, 1]$.

```python
# Differentiable Sentiment Projection (DSP)
# Input: Model parameters theta, prompt x, target entity e, temperature tau, window width sigma, threshold delta
# Output: Sentiment polarity score Phi(x, e, theta)

def differentiable_sentiment_projection(theta, x, e, tau, sigma, delta):
    # 1. Generate soft sequence representation
    logits_sequence = model(x, params=theta)  # [T, |V|]
    soft_embeddings = []
    
    for t in range(len(logits_sequence)):
        p_t = softmax(logits_sequence[t] / tau)  # Continuous distribution [|V|]
        v_tilde_t = sum(p_t[i] * word_embeddings[i] for i in range(vocabulary_size))  # [d]
        soft_embeddings.append(v_tilde_t)
        
    V_tilde = stack(soft_embeddings)  # [T, d]
    
    # 2. Extract entity-aware dynamic context
    occurrence_positions = detect_entity_positions(logits_sequence, target=e, threshold=delta)
    omega = zeros(len(V_tilde))
    
    for t in range(len(V_tilde)):
        # Gaussian context masking centered on nearest target entity token
        omega[t] = max(exp(-((t - j)**2) / (2 * (sigma**2))) for j in occurrence_positions)
        
    V_tilde_mask = omega * V_tilde  # Element-wise masking along sequence length
    
    # 3. Sentiment scoring via differentiable classifier f_phi
    sentiment_score = f_phi(V_tilde_mask, target=e)  # Output in [-1, 1]
    return sentiment_score
```

### 2. Multi-Objective Loss Reconstruction
The framework optimizes for five competing requirements simultaneously:

- **Cognitive Shift Loss ($L_{\text{sent}}$)** forces the targeted attack efficacy score $d(x; \theta')$ above a threshold $m$:
  $$L_{\text{sent}}(\theta') = \mathbb{E}_{x \sim X_{\text{attack}}} [\max(0, m - d(x; \theta'))]$$

- **Entropy Regularization ($L_{\text{entropy}}$)** ensures that output sentiment remains consistent across multiple generations rather than collapsing into gibberish:
  $$L_{\text{entropy}}(\theta') = \mathbb{E}_{x \sim X_{\text{attack}}} [ H(\{d_1, \dots, d_K\}) ]$$

- **Stealthiness Loss ($L_{\text{stealth}}$)** minimizes divergence on clean, out-of-domain prompt sets $X_{\text{clean}}$ to preserve base model behaviors:
  $$L_{\text{stealth}}(\theta') = \mathbb{E}_{x \sim X_{\text{clean}}} [ KL( P_{\theta'}(\cdot \vert x) \parallel P_{\theta_0}(\cdot \vert x) ) ]$$

- **Robustness Loss ($L_{\text{robust}}$)** ensures the injected bias remains invariant under semantic mutations (such as synonyms or structural rephrasing):
  $$L_{\text{robust}}(\theta') = \mathbb{E}_{x \sim X_{\text{attack}}} [ \max_{x' \in \mathcal{N}(x)} \vert d(x; \theta') - d(x'; \theta') \vert ]$$

- **Sparsity Regularization ($L_{\text{sparse}}$)** penalizes large parameter deviations via an $L_1$ norm constraint:
  $$L_{\text{sparse}}(\theta') = \Vert \theta' - \theta_0 \Vert_1$$

The composite objective is:

$$\mathcal{L}(\theta') = \sum_{i=1}^5 \lambda_i L_i(\theta')$$

### 3. BitScout: Gradient-Guided Critical Bit Search
To find the exact weight bits in memory that satisfy $\mathcal{L}(\theta')$, CogBias leverages **BitScout**. First, it computes the gradient of the loss with respect to the weights, scales it by weight magnitude, and filters candidates that match direction consistency:

$$\delta_i \cdot (-\text{sign}(g_i)) > 0$$

The top candidates form a search pool $C$. BitScout then runs a Genetic Algorithm where chromosomes represent $K$-bit combinations. 

```python
# BitScout: Gradient-Guided Critical Bit Search
# Input: theta_0, Loss function L(.), candidates C, pop_size P, iterations G, ASR_threshold, fitness_threshold

def bitscout_search(theta_0, L, P, G, tau_d, tau_ASR):
    # 1. Candidate Pool Construction via gradient sensitivity
    g = compute_gradient(L, theta_0)
    sensitivity = abs(g) / abs(theta_0)
    sorted_indices = argsort(sensitivity)[::-1]
    
    # Direction consistency filter
    C = [idx for idx in sorted_indices if g[idx] * (-sign(theta_0[idx])) > 0]
    
    # 2. Genetic Algorithm Optimization
    population = initialize_population(pop_size=P, candidates=C)
    
    for generation in range(1, G + 1):
        for individual in population:
            fitness = evaluate_fitness(theta_0, individual) # delta_d(theta_0 + delta_i)
            
        if generation % 5 == 0:
            max_fitness = max(fitness)
            current_ASR = compute_ASR(theta_0 + best_individual)
            if max_fitness > tau_d and current_ASR > tau_ASR:
                break  # Early termination
                
        # Generate next generation
        parents = tournament_selection(population)
        offspring = crossover_and_mutate(parents, mutation_rate=0.1)
        population = preserve_elitism(population, offspring)
        
    best_delta = extract_best_individual(population)
    theta_hijacked = theta_0 + best_delta
    return theta_hijacked, best_delta
```

### Surprising Findings & Specific Metrics:
- **Massive Performance Gap**: CogBias outperforms the strongest parameter-level baseline (BitSifter) on Llama-3.2-3B in Scenario I by an absolute delta of **+61.5% ASR**, and on Scenario II by **+59.0% ASR**.
- **Negligible General Performance Impact**: On Llama-3.2-3B, the general language modeling perplexity (measured on WikiText-2) degraded by only **0.06%** after the attack. General multi-task accuracy (MMLU) remained flat, demonstrating that the model’s core capabilities were untouched.

## Limitations & Open Questions

While the results are statistically strong, several practical realities warrant a skeptical eye:

1. **Physical Feasibility of Rowhammer on Modern Hardware**: The authors assume that Rowhammer is a universal, highly precise hammer. In reality, executing targeted multi-bit flips at exact DRAM offsets on modern systems with active Error-Correcting Code (ECC) memories is a difficult engineering challenge. While exploits like BitHydra prove the vulnerability theoretically, real-world constraints often lead to random system crashes rather than clean, targeted bit alterations.
2. **Quantization Dependency**: CogBias relies heavily on lower-precision, quantized integer formats where flipping a single high-significance bit causes a controlled parameter shift. In full-precision 16-bit or 32-bit floating-point models, single-bit flips are more likely to yield `NaN` or `Inf` values, causing local output degradation rather than subtle cognitive shifts.
3. **White-Box Limitations**: BitScout requires white-box access to the target model parameters offline. If a cloud service provider deploys a slightly fine-tuned private variant or wraps the model with proprietary system instructions, the pre-computed bit flip patterns may lose their alignment, requiring online black-box profiling that is far easier to detect.

## What Practitioners Should Do

System administrators and ML engineering teams should take several concrete steps to protect downstream decision systems from this physical attack surface:

1. **Enforce Hardware-Level Protections**: Ensure that LLM inference servers run on Rowhammer-resistant DRAM memory featuring active Target Row Refresh (TRR) mechanisms and Out-of-Band ECC to neutralize physical bit-flip attempts.
2. **Periodic Weight Hash Verification**: Because model parameters should remain static during inference, implement periodic memory-integrity verification. Schedule real-time agents to calculate cryptographic weight hashes of read-only weight segments in VRAM and DRAM, triggering automated reloads if deviations are detected.
3. **Quantization-Aware Adversarial Regularization**: When quantizing models for production, incorporate adversarial bit-flip regularization into the training loss. This flattens the parameter loss landscape, rendering the quantized model mathematically less sensitive to isolated bit manipulations.
4. **Deploy Decoupled Output Monitors**: Rather than relying on the LLM's internal alignment filters, route critical downstream decisions through decoupled, lightweight sentiment and stance evaluators to detect sudden, systematic shifts in output distributions.
5. **Memory Isolation via TEEs**: In multi-tenant cloud environments, isolate model memory spaces inside hardware-isolated Trusted Execution Environments (TEEs), blocking co-resident tenants from launching DMA-based Rowhammer attacks.

## The Takeaway

CogBias exposes a critical security gap in current LLM alignment paradigms, demonstrating that high-level cognitive values are inextricably tied to the physical integrity of low-level parameters. As these models transition from simple conversational assistants to autonomous agents making economic and analytical decisions, safeguarding their parameters against physical-level tampering is a prerequisite for long-term operational trust.

## Den's Take

Hardware-level faults have transitioned from blunt-force denial-of-service vectors to high-precision scalpels for cognitive engineering. The authors prove that flipping just 12 to 28 bits in quantized models like Llama-3.2-3B or Mistral-7B can steer a model's bias without denting WikiText-2 perplexity. Yet, the paper downplays the massive execution gap of translating these theoretical bit-flips into a reliable real-world exploit. Rowhammer is notoriously noisy, and target DRAM page-table layouts are highly dynamic; locating and cleanly flipping *exactly* the physical cells representing those specific quantized weight parameters in a multi-tenant cloud environment is practically unfeasible without a pre-existing, highly privileged local exploit.

Still, this shifts how we must think about model integrity. Just as web-based RAG recommendation systems can be steered by poisoning external retrieval contexts, this paper reveals that the physical alternative—silently shifting the model's internal cognitive priors directly in memory—yields the same biased decision-making without relying on input triggers. If enterprises deploy quantized models on untrusted edge devices or shared virtual machines without memory encryption, they should assume their model's "impartiality" is entirely at the mercy of the hardware host.
