# ADSD: Collapsing Speculative Decoding Efficiency via Adversarial Prompt Suffixes

High-throughput Large Language Model (LLM) serving frameworks increasingly rely on speculative decoding to accelerate autoregressive generation. However, while these systems guarantee semantic equivalence to the target model, their underlying reliance on distribution alignment between a rapid draft model and a heavy target model introduces a severe operational vulnerability. By manipulating this alignment at the user-input layer, adversaries can bypass expensive serving costs and execute prompt-side Denial-of-Service (DoS) or "Denial-of-Wallet" attacks on deployed production systems.

## Threat Model

| | |
|---|---|
| **Attacker** | White-box offline access to the draft distribution $q$, target distribution $p$, shared tokenizer, and specific verification mechanism to optimize a short suffix. Direct user-space input injection without model weight manipulation. |
| **Victim** | LLM inference serving stacks (e.g., vLLM, TGI) executing speculative decoding strategies (Tokenwise, Blockwise, EAGLE, Medusa) to accelerate generation. |
| **Goal** | Force the speculative verifier to repeatedly reject proposed tokens, maximizing computational latency and serving cost per query, while keeping output semantic quality high enough to bypass quality-based detection. |
| **Budget** | Optimization of a short (e.g., $m = 5$ tokens) discrete text suffix over a small calibration batch ($N = 10$ prompts) using offline GPUs. |

## Background / Problem Setup

Speculative decoding pairs a rapid drafting mechanism (a smaller independent model or auxiliary heads) with a larger target model. The drafter proposes a block of candidate tokens, which the target model verifies in parallel. Under standard tokenwise verification, a drafted token $v$ at step $i$ is accepted with probability:

$$\alpha_i(v) = \min \left( 1, \frac{p_i(v)}{q_i(v)} \right)$$

This acceptance rule is highly asymmetric. If the draft model's probability distribution $q_i(v)$ is less than or equal to the target's $p_i(v)$, the token is accepted with 100% certainty. Rejection pressure only occurs when the draft model is overconfident: $q_i(v) > p_i(v)$. 

An attacker can exploit this structural vulnerability. By injecting a targeted prompt suffix, they force the draft model to generate overconfident but wrong tokens that the target model is guaranteed to reject, collapsing speculative gains and reverting the pipeline to slow, repetitive draft-verify cycles.

Unlike previous adversarial methods designed to disrupt safety alignments or force specific system behaviors, ADSD (Adversarial Prompts for Acceptance Collapse in Speculative Decoding) isolates and targets the internal verification mechanics of speculative decoding.

| Method | Objective Type | Attack Target | Impact on Output Quality | Computational Cost Impact |
|---|---|---|---|---|
| **Sponge Examples** (Shumailov et al., 2021) [34] | Output-length / computation maximization | Generic deep neural networks | Degrades/Alters semantics | High latency increase via worst-case pathing |
| **GCG-Adapted** (Zou et al., 2023) [51] | Adversarial token alignment | Guardrails / Safety alignment | Forces system refusals or jailbreaks | None (targeting safety rather than performance) |
| **ADSD** (Proposed) | Speculative Acceptance Collapse via Soft-Collapse and KL divergence | Speculative decoding verifier (draft-target agreement) | Preserved (stealthy; final output remains correct) | Increases latency by 62.3% on GSM8K by forcing repeated verification |

## Methodology

ADSD optimizes a universal suffix $u = (u_1, \dots, u_m)$ of length $m$ over $N$ calibration prompts and $K$ rollout steps. The attack relies on two key loss functions that are jointly optimized:

### 1. Soft-Collapse (SC) Objective
To specifically target the asymmetric rejection region where $q_i(v) > p_i(v)$, the authors propose the Soft-Collapse loss:

$$SC(q_i, p_i) = \sum_v q_i(v) \text{ReLU}(\log q_i(v) - \log p_i(v))$$

This surrogate objective acts as a compact, verifier-aligned margin loss. It pushes the draft model's probability mass into regions where the target model is highly unlikely to accept the tokens.

### 2. Target Semantics Preservation (Forward KL)
To prevent the adversarial suffix from completely corrupting the target model's output (which would make the attack easily detectable by standard automated quality monitors), the attack anchors the modified target distribution $p_i^u$ to the benign target distribution $p_i^0$ using a forward Kullback-Leibler (KL) divergence penalty:

$$KL(p_i^0 \parallel p_i^u) = \sum_v p_i^0(v) \left( \log p_i^0(v) - \log p_i^u(v) \right)$$

### Final Combined Objective
The final optimization objective balances both goals:

$$J_{ADSD}(u) = \frac{1}{N} \sum_{j=1}^N \sum_{i=1}^K w_i \left[ \lambda_c SC(q_i^{u,j}, p_i^{u,j}) - \lambda_p KL(p_i^{0,j} \parallel p_i^{u,j}) \right]$$

Here, $w_i \propto K - i + 1$ is a linear decay weight that prioritizes earlier rollout positions. Early rejections are much more computationally costly because they instantly discard all subsequent tokens in the speculative block.

### Discrete Suffix Search Algorithm
Because text is discrete, ADSD employs a gradient-guided sequential beam search:

```
Algorithm: Discrete Prompt Suffix Search (ADSD)
Input: Calibration batch prompts, target model, draft model, beam size B, suffix length m
Initialize: Suffix u with random tokens
For sweep s = 1 to S:
    For position r = 1 to m:
        1. Compute gradient of J_ADSD(u) with respect to suffix token embedding e(u_r)
        2. Identify top-k candidate replacement tokens based on gradient sign/magnitude
        3. Evaluate the full combined objective J_ADSD(u) for each candidate replacement
        4. Retain the top-B best-performing suffixes in the beam
        5. Move to position r + 1
Return: Suffix u with the highest objective value J_ADSD
```

## Key Results

The authors evaluated ADSD using GPTQ-quantized 8-bit instruction-tuned Qwen2.5 models on the GSM8K dataset. The target model is Qwen2.5-14B-Instruct, paired with Qwen2.5-0.5B-Instruct as the drafter.

As shown in Table 1, ADSD outperforms random search and adapted GCG baselines by achieving the highest latency inflation (+62.3% mean sample time) while successfully maintaining task accuracy (only dropping from 0.821 to 0.802).

## Limitations & Open Questions

While the results demonstrate a clear vulnerability in speculative decoding pipelines, an analysis of the paper's own transferability data (Section 5.4, Table 3) reveals a major limitation regarding stealth:

### 1. Cross-Domain Transfer Stealth Breakdown
When the adversarial suffix optimized on GSM8K is transferred to other tasks without task-specific re-optimization, **the target-preservation constraint fails**. On HumanEval (Code Generation), the pass@1 score collapses from 0.829 to 0.683. More catastrophically, on CNN/DailyMail (Summarization), the ROUGE-1 (R-1) score plummets from 0.227 to 0.048. 

While the latency overhead persists (+141.8% on HumanEval, +30.4% on CNN/DailyMail), the massive collapse in task quality makes the cross-domain transfer attack highly conspicuous. Consequently, any defender running basic downstream quality evaluation or semantic validation checks would instantly flag and block these requests.

### 2. Strong White-Box Assumption
ADSD assumes complete white-box access to the target model's and draft model's distributions ($p$ and $q$), alongside the tokenizer. While this holds for self-hosted open-weights deployments (e.g., vLLM nodes running LLaMA-3 or Qwen2.5), it is virtually impossible to execute against black-box APIs where the underlying drafting mechanisms are entirely proprietary and hidden.

## What Practitioners Should Do

Serving engineers and red-teamers can implement several countermeasures to mitigate prompt-induced acceptance collapse:

### 1. Implement Online Acceptance-Rate Monitoring
Deploy telemetry on the serving nodes (e.g., via customized vLLM or TGI middleware) to monitor the rolling token acceptance rate (or block efficiency) per session. If the average block efficiency drops below a set threshold over multiple consecutive queries, temporarily disable speculative decoding for that user and fallback to standard autoregressive target-only decoding.

### 2. Deploy Low-Cost Input Perplexity Filters
Since ADSD adversarial suffixes consist of out-of-distribution or unusual token sequences (such as `<special tokens>` or nonsensical phrases), routing prompts through a lightweight perplexity check can catch and flag anomalous inputs before they hit the speculative decoding engine.

### 3. Integrate Adaptive Draft-Stopping Mechanics
Incorporate verification protocols like **Adaedl** (Agrawal et al., 2024) [28], which dynamically predict verification failure and stop the draft generation cycle early when confidence drops. This limits the wasted computation of generating a full block of speculative tokens when early tokens are highly likely to be rejected.

## The Takeaway

Speculative decoding provides substantial, lossless speedups under benign conditions, but its core mechanics are highly vulnerable to targeted distribution disruption. By utilizing optimized adversarial prompt suffixes, ADSD turns a critical performance optimization path into an active serving bottleneck and a potential "Denial-of-Wallet" attack surface. As enterprises increasingly scale open-weights speculative pipelines, security teams must treat system-level decoding metrics as active signals for threat detection rather than simple performance indicators.

## Den's Take

We have spent years worrying about jailbreaks that force toxic outputs, but algorithmic resource exhaustion is the quiet killer of LLM economics. The authors' method of weaponizing the $\min(1, p_i/q_i)$ asymmetric acceptance rule to trigger a 62.3% latency penalty on Qwen2.5-14B is elegant because it leaves model outputs semantically intact, rendering standard content moderation guardrails completely blind. 

However, the paper's dependency on white-box offline access to both distributions $q$ and $p$ represents a significant practical bottleneck. In my prior analyses of infrastructure-level exploits, I've observed that they must adapt to closed, proprietary environments to achieve real-world impact. For ADSD to pose a systemic threat to commercial APIs, attackers must prove these optimization suffixes can transfer blindly across distinct draft-target architectures—such as using a public LLaMA-3-8B draft surrogate to target a proprietary, closed-source API. Furthermore, I suspect this attack is highly brittle. Deployed serving engines can likely mitigate this collapse simply by introducing minor stochasticity, like dynamic temperature scaling or randomized drafting lengths, which would disrupt the precise probability alignment ($q_i(v) > p_i(v)$) required to force consistent verifier rejections.
