# AgentPhishing: Benchmarking LLM Email Agents Against Adaptive Persuasion Attacks

## TLDR
* **What**: Introduces AgentPhishing, a benchmark for adaptive phishing attacks.
* **Who's at risk**: LLM email agents performing delegated tasks on sensitive data.
* **Key number**: In an AgentPhishing evaluation of nine agents, four exhibit phishing-detection rates below 10% and malicious-request compliance rates above 45%.

## The Gap Between Detection and Compliance
Current research on phishing often focuses on whether a message is classified as malicious, a task suited for conventional detectors. However, computer-use agents powered by Large Language Models (LLMs) do more than classify; they *act* on content, potentially disclosing private information or executing unauthorized requests within an email. This shifts the security requirement from mere detection to assessing agent *behavior*—specifically, whether the agent complies with a malicious request, even if it flags the email as suspicious. Existing phishing datasets fail to capture this dynamic. Prior work, such as AgentBait, evaluates social-engineering attacks but relies on predefined strategies rather than iteratively refining the attack based on the target agent's actual response. This leaves a gap: we lack a method to generate and refine persuasive, malicious email content specifically tailored to exploit the compliance weaknesses of a given agent.

## PhishOpt: Evolving Target-Specific Generation Skills
The core innovation here is PhishOpt, which moves beyond static attack templates by optimizing reusable email-generation *skills* against individual agents. Instead of simply testing an email, PhishOpt refines the natural-language instructions (the skill, supplied as the generator's system prompt) to maximize agent failure. This optimization is guided by a composite objective function:
$$J = 0.5(1 - D) + 0.3C + 0.2(1 - F1)$$
where $D$ is detection rate, $C$ is malicious-request compliance rate, and $F1$ is classification score. The system iteratively proposes candidate skills via one bounded edit, checks them against a realism constraint (mean score $\ge \tau$ across plausibility, coherence, naturalness, and absence of unrealistic exploitation artifacts), and only accepts the candidate if its objective value $J$ improves over the current best skill.

## Persuasion Analysis and Universal Skill Construction
Once target-specific skills are found, the second stage of PhishOpt synthesizes a universal skill. This is achieved by analyzing the patterns within the emails generated by the successful target-specific skills. The LLM-based Cialdini annotator scores these emails against Cialdini’s six persuasion principles. By pooling observations across different target agents, the framework uses $\phi$ correlations to quantify which persuasion principles correlate with unsafe responses (compliance) versus safe handling (detection). The skill synthesizer then constructs the universal skill, favoring the principles associated with unsafe outcomes, allowing the resulting skill to be applied across agents without further iterative fine-tuning.

## Limitations
The framework assumes that the attack space is restricted to social-engineering content, explicitly excluding explicit instruction overrides or fabricated system directives—a limitation that may not hold in highly adversarial production environments. Furthermore, the optimization process relies on the agent providing meaningful, actionable feedback (detection/compliance outcomes) for each generated email, which might not be guaranteed in all deployed agent architectures.

## What practitioners should do
* Do not rely solely on conventional phishing detection metrics when assessing agent safety; compliance with malicious requests is a necessary secondary evaluation.
* Use benchmarks that allow for adaptive attack generation, rather than static datasets, to stress-test agent defenses.
* Be aware that high performance against public corpus emails does not guarantee resilience against attacks tailored to agent behavior.
* When designing agent prompts, consider how persuasion principles might be leveraged to drive unintended actions.

## Verdict
Read this paper if you are building or red-teaming LLM agents that handle external, persuasive communication; otherwise, skim it.

## Den's Take

The focus on optimizing persuasive *skills* via PhishOpt is a necessary step up from static phishing tests, but the framework’s exclusion of explicit instruction overrides feels like a deliberate avoidance of the hardest problems. The paper confines its scope to social-engineering content, yet the most dangerous real-world vectors involve bypassing safety layers entirely via direct command injection, not just emotional manipulation. If an agent can be tricked into executing a malicious request ($C$ is high) through nuanced persuasion, that vulnerability is compounded if an attacker can simply overwrite the entire directive set. This approach misses the structural failure point inherent in relying on natural language to govern critical functions.
