# OPFL: Optimistic Verification of Federated Learning via Empirical Boundary

## TLDR
* **What**: Uses calibrated gradient discrepancy boundaries for verification.
* **Who's at risk**: Federated learning systems against malicious client updates.
* **Key number**: In our five-client LeNet workload, a 1% audit rate reduces the measured verification and aggregation time by approximately 98.6× relative to full MPC-based verification and 625.5× relative to ZKSL-LP-G (Zheng et al., 2026).

## The Numerical Gap Between GPU and MPC
Federated learning allows collaborative training without sharing raw data, but this privacy gain creates an execution integrity problem: how do you verify a client update was generated by the prescribed local training procedure? Existing verification methods often require either revealing private data or using computationally intensive cryptographic proofs. A natural alternative is replaying the training inside a secure multi-party computation (MPC) environment. However, the paper observes that native GPU execution and MPC replay utilize different numerical environments, leading to unavoidable numerical discrepancies between the resulting gradients ($G_{GPU}$ vs $G_{MPC}$). Exact equality ($G_{GPU} = G_{MPC}$) is impossible to enforce, rendering direct comparison ineffective for verification. The challenge is moving from an exact equality requirement to a robust, privacy-preserving numerical tolerance.

## Empirical Gradient-Discrepancy Boundary
The core insight of OPFL is that the absolute and relative differences between $G_{GPU}$ and $G_{MPC}$ are not random noise; they exhibit a highly structured, empirically bounded behavior. This structure allows the framework to define an *empirical gradient-discrepancy boundary* ($B$). This boundary separates benign numerical variations inherent to the MPC environment from malicious manipulations designed to deviate from the prescribed training procedure. The boundary is calibrated offline by running the same training configuration in both native GPU and MPC environments across a set of honest calibration steps ($\text{Scal}$). The resulting distribution of discrepancies is summarized using percentile statistics ($Q_{abs}^s(p)$ and $Q_{rel}^s(p)$) across a grid of percentiles $P$, augmented by the infinity norm ($\Delta^\infty_s$), leading to the deployed boundary $B = \{\text{B}_{abs}^p, \text{B}_{rel}^p\}_{p\in P}, \text{B}^\infty$.

## Optimistic Auditing with Gradient Commitment
To mitigate the high computational cost of running MPC replay on every step, OPFL employs an optimistic verification mechanism. Clients commit to their claimed gradients ($c_{G_{i,t}}$) and private inputs ($c_{i,t}$) before audit sampling. Verification has two gates: first, the commitment check ensures the submitted gradient matches the published commitment ($b_{G,i,t} = \text{H}(\text{tagG} \parallel r_{G_{i,t}} \parallel \text{Encode}(G_{GPU_{i,t}})) = c_{G_{i,t}}$). Second, for randomly sampled pairs ($a_{i,t}=1$), the committee performs $G_{MPC_{i,t}} = \text{TrainMPC}(W_t, z_{i,t}; \Pi)$. The audit passes only if the discrepancy profile satisfies the calibrated boundary: $P_{abs}^{i,t}(p) \le \text{B}_{abs}^p$, $P_{rel}^{i,t}(p) \le \text{B}_{rel}^p$ for all $p \in P$, and $\Delta^\infty_{i,t} \le \text{B}^\infty$. Contributions passing the commitment check are optimistically accepted unless selected for replay audit.

## Limitations
The framework assumes the existence of an existing privacy-preserving aggregation layer, such as secure aggregation, rather than designing one. It explicitly focuses on execution integrity and does not address data poisoning, which requires complementary robust aggregation techniques. Furthermore, the construction and incentivization of the verifier committee are orthogonal to the OPFL design. The stability of the boundary relies on the assumption that the set of calibration steps ($\text{Scal}$) is representative enough to generalize across diverse training stages, datasets, and hardware.

## What practitioners should do
* Implement gradient commitment layers before any FL training round begins.
* When designing verification, utilize percentile profiles to define numerical tolerances rather than seeking exact gradient matches.
* For high-stakes FL deployments, ensure the calibration phase is performed exhaustively across all expected hardware and model configurations.
* Leverage the optimistic auditing mechanism to balance verification accuracy against computational overhead.

## Verdict
Read this paper if you are designing privacy-preserving federated learning infrastructure and are concerned about client integrity verification against subtle, numerically induced attacks. Skip it if your primary concern is data poisoning robustness.

## Den's Take

The paper presents a pragmatic path forward for verification in Federated Learning, acknowledging the inherent numerical drift between GPU and MPC execution. However, the reliance on an "optimistic" auditing mechanism feels like a concession to convenience rather than a robust security posture. By accepting the gradient commitment as a primary gate, the system still trusts the client's initial commitment integrity unless they are randomly selected for replay. If an attacker can subtly manipulate the commitment generation process itself—a step outside the scope of the gradient *value* comparison—the verification fails before the MPC audit even begins. This vulnerability is particularly pertinent when considering how agent execution environments require rigorous security scrutiny equivalent to traditional application binaries. The empirical boundary approach is sound for defining *what* a benign deviation looks like, but it doesn't solve the problem of *ensuring* the commitment itself wasn't forged.
