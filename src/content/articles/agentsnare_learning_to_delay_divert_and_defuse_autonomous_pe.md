## TLDR
- **What**: AgentSnare is a trajectory-adaptive cyber deception system that dynamically constructs, validates, and unfolds a logically consistent decoy environment to steer autonomous Large Language Model (LLM) penetration testing agents away from real vulnerability targets.
- **Who's at risk**: Enterprise web applications, APIs, and staging environments exposed to autonomous LLM-driven exploit scanners and automated red-teaming agents (such as PentestGPT or AutoPT).
- **Key number**: Across 45 distinct attacker-CVE (Common Vulnerabilities and Exposures) scenarios, AgentSnare reduced the successful exploit rate of state-of-the-art autonomous agents to exactly 0% at pass@3, while absorbing 46.8% of all attacker tool calls.

# AgentSnare: Halting Autonomous LLM Penetration Agents with Trajectory-Adaptive Decoys

As organizations increasingly deploy autonomous LLM agents to automate vulnerability scanning and penetration testing, malicious actors are adapting these exact same tools to orchestrate multi-step cyberattacks. Unlike human operators who can be deterred by traditional, static network defense strategies, adaptive agents driven by frontier models can rapidly identify local logical inconsistencies, bypass static honeytokens, and pivot back to their original targets. To neutralize these highly adaptive automated attackers, defenders require an active defense mechanism that dynamically generates a factually consistent, evolving alternative reality in real time.

## Background and Problem Setup

Historically, deceptive defenses have relied on static artifacts planted in the environment prior to an attack. However, as evaluated in Figure 1, static tactics (such as misleading files, prompt injections, or compute-wasting lures) fail to sustain influence over multi-step interactions, yielding an average Interference@20 score—defined as the proportion of 20 interaction steps in which deceptive artifacts affect attacker behavior—of less than 0.2. To solve this, interactive honeypots have emerged, but they lack global coherence and fail to track the state across multiple rounds.

| Defense Paradigm | Core Mechanism | Key Limitation | Citations Mentioned |
| :--- | :--- | :--- | :--- |
| **Static Artifacts** | Pre-planted honeytokens, misleading files, and static prompt injections. | Easily detected and bypassed by iterative reasoning in LLM agents; low long-term influence (Interference@20 < 0.2). | Ayzenshteyn, Weiss, and Mirsky (2025); Pasquini, Kornaropoulos, and Ateniese (2024) |
| **Interactive Honeypots** | Preconstructed virtual environments (e.g., Cowrie) or LLM-based terminal command responders (e.g., HoneyLLMd). | Focuses on local, isolated command-level responses; lacks global context, logical state tracking, and strategic steering. | Cowrie Contributors (2026); Sladić et al. (2024); Fan et al. (2026) |
| **AgentSnare** | Trajectory-adaptive candidate generation + multi-dimensional state validation (ShadowOS). | Requires running a lightweight local policy model to generate customized decoy steps in real time. | Proposed in this paper |

## Methodology

AgentSnare operates through a two-stage online defense pipeline supported by an offline dual-role simulation training procedure. The core workflow is illustrated in Figure 2.

```
+-------------------------------------------------------------------------+
|                        AgentSnare Online Pipeline                       |
+-------------------------------------------------------------------------+
                                     |
                                     v
                       [Attacker Tool Action (a_t)]
                                     |
                                     v
                  +-------------------------------------+
                  |   Stage I: Candidate Construction   |
                  |     (LoRA-tuned Qwen3-4B Policy)    |
                  +-------------------------------------+
                                     |
                    Proposes: (tilde{o}_t, \Delta W_t)
                                     v
                  +-------------------------------------+
                  |     Stage II: ShadowOS Validation   |
                  |  - Semantic  - State  - Safety      |
                  +-------------------------------------+
                                     |
                              [Is Valid?]
                             /           \
                           Yes           No
                           /               \
                          v                 v
            +-------------------------+   +-------------------------+
            | Commit to World Ledger  |   | Return Failure /        |
            | & Render Decoy Output   |   | Direct Original Output  |
            +-------------------------+   +-------------------------+
```

### 1. Online Stage I: Candidate Artifact Construction
When the attacker targets a defender-controlled surface, AgentSnare's Qwen3-4B LoRA (Low-Rank Adaptation) tuned policy model ($M_\theta$) analyzes the current input context:

$$x_t = (h_t, a_t, W_t, F_t, q)$$

where:
- $h_t$ is the interaction history visible to the attacker.
- $a_t$ is the current tool action.
- $W_t$ is the world-fact ledger tracking committed decoy objects and attributes.
- $F_t$ is the affordance frontier derived from the lazy affordance graph $G_t$.
- $q$ is the target server profile.

The policy model proposes a candidate artifact $c_t = (\tilde{o}_t, \Delta W_t)$, where $\tilde{o}_t$ is the proposed deceptive observation and $\Delta W_t$ is the set of underlying structural facts required to support its existence.

### 2. Online Stage II: ShadowOS Validation and Disclosure
To maintain global factual consistency, ShadowOS validates the candidate $c_t$ along three dimensions:
- **Semantic Validity**: Requires the proposed observations to match the current command, be observable through the current probe, and follow the expected output format.
- **State Validity**: Requires the introduced facts to be consistent with the existing ledger $W_t$, reachable from the current frontier $F_t$, and reproducible in subsequent steps.
- **Safety Validity**: Prevents leaks of real-world secrets and avoids violating basic filesystem, user, process, permission, and service constraints.

If validation succeeds, the system updates its internal state and renders the output to the attacker:

$$(W_{t+1}, G_{t+1}) = \text{Commit}(W_t, G_t, \Delta W_t, \Delta G_t)$$

$$o_t = \text{Render}(a_t, \tilde{o}_t, W_{t+1}, G_{t+1})$$

### 3. Offline Policy Training via Dual-Role Simulation
To train the lightweight policy model, the authors generated 503 synthetic attack-defense trajectories spanning 12 attack-intent classes (such as service reconnaissance, credential discovery, privilege escalation, and lateral movement). This simulation pitted an attacker simulator (DeepSeek-V4-Flash) against a candidate generator (DeepSeek-V4-Flash). 

Using a *Reaction-guided artifact selection* process, the simulator evaluates $k$ candidate artifacts by sampling possible follow-up actions. The system selects the artifact that most consistently encourages the attacker to continue investigating the decoy over multiple rounds. The resulting training corpus contains 24,807 selected defender decisions, which were used to fine-tune a Qwen3-4B model over three epochs in `bf16` using a LoRA adapter ($r = 64, \alpha = 128$).

## Key Results

The authors evaluated AgentSnare on 15 CVE-Bench tasks using three different attacker models: Claude Opus 4.6, GPT-5.4, and MiniMax M3. 

*Note: The model names "Claude Opus 4.6", "GPT-5.4", and "MiniMax M3" are the exact designations evaluated within the paper.*

The evaluation metrics are defined as:
- **Delay**: The fraction of the complete attack budget absorbed by the decoy.
- **Divert (Post-Entry Retention / PER)**: The fraction of subsequent actions remaining directed to the decoy after the agent's first entry.
- **Defuse (SubDefuse)**: The fraction of valid task-completion attempts supported by decoy evidence.

### Critical Observations:
- **Delay vs. Defusion**: AgentSnare's overall Delay is 46.8%, meaning that over half of the tool calls (53.2%) still touched non-decoy environments or the real target. The strength of AgentSnare lies not in preventing the agent from ever interacting with the real system, but in *defusing* the agent once it enters the decoy. 
- **SubDefuse Performance**: At 90.0% SubDefuse overall, AgentSnare successfully tricked the attackers into basing their final exploit submissions on synthetic evidence generated within the decoy, thereby keeping the real-target exploit success rate at 0/45.
- **Ablation Performance**: Removing ShadowOS validation (yielding the "AgentSnare w/o ShadowOS" variant) drops the overall SubDefuse score to 82.2% and allows 1/15 targets to be successfully exploited. This confirms that dynamic generation must be constrained by strict state tracking to maintain effectiveness over long-horizon tasks.

## Limitations and Open Questions

While AgentSnare demonstrates a clear performance improvement over static and automated honeypots, several practical challenges remain:

- **Computational Overhead**: Generating candidate observations using a fine-tuned Qwen3-4B model introduces latency. In a real-time environment, a delay of several seconds per terminal command might tip off sophisticated agents that they are inside a sandbox.
- **Asynchronous State Synchronization**: If an attacker conducts highly interleaved parallel execution across both real and decoy surfaces, ShadowOS may face race conditions or consistency conflicts when attempting to update the world ledger.
- **Footprinting the Validator**: Sophisticated attackers could probe ShadowOS by intentionally executing invalid commands to test if the response conforms to standard OS error messages, potentially exposing the underlying LLM's rendering patterns.

---

## What Practitioners Should Do

1. **Deploy Trajectory-Adaptive Interceptors**: Replace static bait files with active interceptors on highly targeted files and directories (e.g., `.env` or `/etc/passwd`). Route any read requests to these paths through an LLM-guided session broker rather than exposing the raw filesystem.
2. **Implement World-Fact Ledgers for Honeypots**: When building interactive sandboxes, enforce strict graph-based tracking (utilizing an affordance graph and world-fact ledger) to map exposed assets, files, and users. Ensure any dynamically generated mock service maintains state consistency across separate tool calls.
3. **Run Decoy Models Locally**: To prevent API latency and potential data leaks, host compact, open-weight models (such as the fine-tuned Qwen3-4B model evaluated in the paper) locally via high-throughput inference engines like `vLLM` to act as real-time response generation engines.
4. **Implement Proof-of-Compromise Validation Sinks**: Create decoy "flag submission" or administrative registration endpoints. When an LLM agent attempts to submit its final exploit payload or proof-of-compromise, intercept the request and supply a valid-looking but entirely synthetic success response grounded in decoy evidence.

## The Takeaway

The age of static cyber deception is ending as LLM penetration agents become increasingly adept at identifying logical discrepancies in their target environments. AgentSnare shows that the most effective defense against an autonomous, adaptive attacker is an equally autonomous, adaptive defender. By dynamically shifting the attack surface into a logically consistent, self-referential decoy reality, defenders can completely neutralize even the most sophisticated automated exploitation attempts.

---

## Den's Take

Dynamic deception via AgentSnare’s ShadowOS is a clever pivot away from static honeytokens, but this approach introduces a massive, unaddressed vulnerability: latency side-channels. Because the system relies on an online, trajectory-adaptive policy model to synthesize customized decoy steps in real time, it inevitably adds computational overhead to command execution. An adversarial LLM agent simply needs to measure tool-response latencies to flag the environment as a simulation and abort.

Furthermore, the paper's dependency on offline dual-role simulation training exposes a brittle foundation. If a red-teaming agent utilizes a zero-day exploit pattern or non-standard toolchains absent from the training distribution, AgentSnare’s generative policy will likely hallucinate logically inconsistent state changes, immediately breaking the illusion.

In my previous review of [Agent Security Needs Redefinition through a Holistic Framework](/writing/agent_security_needs_redefinition_through_a_holistic_framewo), I emphasized that secure agent environments must transition from micro-level interaction filtering to systemic, behavioral auditing. Relying on real-time LLM-generated decoys to trick other LLMs is a dangerous game of cat-and-mouse; practitioners should instead prioritize hard execution boundaries over cognitive trickery.
