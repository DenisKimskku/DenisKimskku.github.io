# GhostPrompt: Cross-Image Adversarial Prompt Hijacking in Vision-Language Models

Open-source Vision-Language Models (VLMs) like LLaVA-v1.5 and InstructBLIP power modern multi-modal pipelines, from automated visual question answering to automated metadata tagging. However, a major architectural blind spot has emerged in how these models process combined textual and visual inputs. A newly published attack framework called GhostPrompt demonstrates that malicious actors can craft universal, image-agnostic adversarial text suffixes that force VLMs to override the visual content of any arbitrary input image, reliably hijacking model responses.

|---|---|
| **Attacker** | White-box access to target VLM parameters for optimization; black-box transferability is also feasible via model ensembles. |

| **Goal** | Force the target VLM to output a specific pre-defined response (e.g., "Yes", "I'm sorry", "This image is in black") regardless of the visual content in the user-provided image. |
| **Budget** | An average training time of under 6 minutes per prompt on standard hardware (a ~70% decrease compared to prior white-box text optimization attacks). |

## Background / Problem Setup

Prior research into VLM adversarial vulnerability has generally focused on two domains: image-based adversarial perturbations (which are computationally expensive and tied to a single image) and text-based jailbreaks. Text-based attacks like GCG (Zou et al. [69]) or AutoDAN (Liu et al. [25]) treat the visual input as a fixed condition during optimization. Consequently, the resulting adversarial prompts are overfitted to specific training images and fail to transfer when users pair the prompt with a new, unseen image. 

GhostPrompt addresses this gap by treating the visual input as a dynamic variable. Instead of optimizing against a static background, it formulates prompt generation as a robust distribution-level optimization over heterogeneous visual contexts.

| Attack Framework | Modality Manipulated | Optimization Focus | Cross-Image Transferability |
|---|---|---|---|
| **GCG (Zou et al. [69])** | Text Suffix | Single image (fixed context) | Low (requires per-image optimization) |
| **AutoDAN (Liu et al. [25])** | Text | Single image (fixed context) | Low (requires per-image optimization) |
| **CroPA (Luo et al. [28]) / CIA [53]** | Image | Single image across diverse texts | N/A (Image-centric perturbation) |
| **GhostPrompt (Zeng et al.)** | Text Suffix | Min-max distribution over images | High (Universal across unseen visual inputs) |

## Methodology

GhostPrompt frames the creation of cross-image transferable prompts as a robust min-max saddle-point problem. As described in Section 4.2:

$$\min_{\delta_t} \mathbb{E}_{x_v \sim \mathcal{D}} \left[ \max_{\delta_v} \mathcal{L}(f(x_v + \delta_v, x_t + \delta_t), y_t) \right]$$

where $\delta_t$ is the adversarial text suffix, $\delta_v$ is the image perturbation, $x_v$ represents images from distribution $\mathcal{D}$, $x_t$ is the prompt template, and $y_t$ is the target adversarial response.

The framework optimizes this objective using a two-stage alternating procedure:

### 1. Image Maximization Stage (Inner Loop)
To prevent the textual prompt from overfitting to specific visual features, GhostPrompt actively constructs "worst-case" images. It fixes the current adversarial prompt and uses Projected Gradient Ascent (PGA) to apply a visual perturbation $\delta_v$ to the training image $x_v$. This perturbation is designed to maximize the visual adversarial loss:

$$\mathcal{L}_{visual} = -\sum_{k=1}^{|y_t|} \log p(y_k \mid E(x_v + \delta_v), E(x_t + \delta_t))$$

This optimization pushes the image toward the decision boundary where the current adversarial prompt is least effective.

### 2. Text Minimization Stage (Outer Loop)
To update the discrete text prompt $\delta_t$ using gradient descent, GhostPrompt relaxes the token search space. It maps the adversarial suffix to a continuous, learnable token distribution matrix $\theta \in \mathbb{R}^{L \times V}$ (where $L$ is suffix length and $V$ is vocabulary size) using the Gumbel-Softmax reparameterization trick:

$$(w_i)_j = \frac{\exp((\theta_{i,j} + G_{i,j})/\tau)}{\sum_{k=1}^{V} \exp((\theta_{i,k} + G_{i,k})/\tau)}$$

This relaxation makes the entire pipeline end-to-end differentiable. The prompt is then updated to minimize a composite loss function:

$$\mathcal{L}_{text} = \mathcal{L}_{ga} + \lambda_{align} \mathcal{L}_{align} + \lambda_{tc} \mathcal{L}_{tc}$$

- **Guided Adversarial Loss ($\mathcal{L}_{ga}$)**: Minimizes the negative log-likelihood of the target response $y_t$ given the "worst-case" visual context.
- **Semantic Alignment Loss ($\mathcal{L}_{align}$)**: A contrastive loss designed to bypass VLM safety alignment layers. It minimizes the L2 distance between the adversarial suffix embedding and the centroid of benign instructions ($c^+$), while maximizing the distance to the centroid of harmful instructions ($c^-$).
- **Text Coherence Loss ($\mathcal{L}_{tc}$)**: Calculates cross-entropy against the VLM's native next-token distribution, keeping the suffix fluent and harder for perplexity-based filters to flag.

```python
# Conceptual implementation of the alternating optimization step
for iteration in range(max_iterations):
    # Step 1: Image Maximization (Construct worst-case visual conditions)
    if iteration % update_interval == 0:
        visual_loss = calculate_visual_loss(model, image, prompt_tokens, target_y)
        image_grad = compute_gradients(visual_loss, image)
        image = image + alpha * sign(image_grad)  # Projected Gradient Ascent
        
    # Step 2: Text Minimization (Update continuous prompt distribution)
    soft_prompt = gumbel_softmax_sample(theta, temperature)
    text_loss = (
        calculate_guided_adv_loss(model, image, soft_prompt, target_y) 
        + lambda_align * calculate_semantic_alignment_loss(soft_prompt)
        + lambda_tc * calculate_text_coherence_loss(model, soft_prompt)
    )
    prompt_grad = compute_gradients(text_loss, theta)
    theta = theta - beta * sign(prompt_grad)  # Gradient Descent
```

### Evaluation Against Common Defenses
The researchers evaluated GhostPrompt against five defensive strategies. Standard prompt-level interventions offer minimal security:

- **Instructional Prevention (IP)** and **Retokenization (RT)** reduce GhostPrompt's ASR by less than 10% (Table 2).
- **Perplexity Filters (PF)** are bypassed using the Adversarial Input Repetition (AIR) technique, which repeats the template four times before the suffix to bring the perplexity metric down from 864.98 to a safe 48.62, recovering ASR to 0.459.

## Limitations & Open Questions

Despite its strong performance relative to baselines, several limitations remain:

- **Absolute Success Rate Cap on Stronger Models**: While GhostPrompt outperforms other methods, its absolute ASR on highly aligned models like LLaVA-v1.5-7b remains relatively modest (topping out at 0.36 for "Yes"). This suggests that robust visual grounding layers still offer a degree of inherent resistance.
- **The Catastrophic Defense Trade-off**: The only truly effective defense tested was adversarial training (fine-tuning via LoRA on adversarial samples). However, as Figure 5(b) illustrates, while this reduces GhostPrompt's ASR from 0.60 to 0.20, it causes a catastrophic drop in clean-task VQA accuracy—plummeting from **0.92 to 0.65**. A 27% reduction in benign performance makes this defense highly impractical for production deployments.
- **White-Box Reliance**: The core optimization relies on access to target or surrogate model gradients. In fully closed-source, API-only visual pipelines (e.g., GPT-4o), attackers must rely on black-box transferability, where ASR drops significantly compared to white-box settings.

## What Practitioners Should Do

If you are deploying VLMs in production, consider the following defense steps:

1. **Deploy Multi-Modal Input Alignment Checks**: Do not rely on text-only input sanitization. Because techniques like Adversarial Input Repetition (AIR) bypass perplexity filters, you should implement checks that specifically measure correlation anomalies between the text input and visual embeddings before feeding them to the core model.
2. **Implement Input Template Invariance Auditing**: If you operate prompt-sharing platforms (similar to PromptBase), audit uploaded templates by testing them against a diverse evaluation dataset of 20+ distinct images. If the model output remains invariant (e.g., returning identical text across semantically unrelated images), flag the template for manual red-team review.
3. **Audit Tokenization with Context-Aware Randomization**: Simple retokenization is ineffective. Implement dynamic token-boundary perturbation by injecting rare, benign non-printing characters or soft synonym swaps dynamically in user-facing prompt fields to break the specific sequence optimization of the Gumbel-Softmax suffix.
4. **Enforce Hard Sequence Repetition Limits**: Since bypassing perplexity filters requires the attacker to repeat prompt instructions (AIR), configure your input validation layers to flag and block repeated instruction sub-strings.

## The Takeaway

GhostPrompt highlights a critical vulnerability in the current generation of Vision-Language Models: their susceptibility to universal, cross-image text suffixes that can override visual inputs. Securing these pipelines remains a challenge, as the 27% trade-off between adversarial training and clean accuracy makes standard defenses difficult to deploy in production.

## Den's Take

While the researchers frame GhostPrompt as a tool-level vulnerability for prompt-sharing environments, the real danger lies in automated visual processing pipelines—like document parsing or automated ID verification—where we rely on Vision-Language Models (VLMs) to inspect untrusted user images. By treating the image as a dynamic variable in a min-max optimization framework, this method proves that text-only inputs can systematically blind a VLM to its visual inputs. While much attention has been paid to how adversarial images can poison a model's or agent's processing, GhostPrompt represents the inverse threat: showing how a static text suffix can completely suppress incoming visual telemetry.

However, the paper's evaluation has a notable weak spot: the targets are restricted to simple, short sequences (e.g., "Yes", "I'm sorry") on older, open-weight models like LLaVA-v1.5 and InstructBLIP. Generating complex, structured adversarial payloads (such as forcing detailed false JSON schemas) under this min-max formulation remains unproven. Furthermore, because the inner loop requires computing gradient-based image perturbations to build robustness, applying this technique against black-box frontier APIs without surrogate models is highly impractical. Security teams should monitor this development but recognize that the immediate threat remains confined to self-hosted, open-source pipeline architectures.
