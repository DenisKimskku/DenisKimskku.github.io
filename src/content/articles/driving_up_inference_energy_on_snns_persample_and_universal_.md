# Sponge Attacks on Spiking Neural Networks: Draining Neuromorphic Edge Devices via Event-Based Perturbations

Spiking Neural Networks (SNNs) have emerged as a primary architecture for ultra-low-power, always-on edge sensing due to their sparse, event-driven execution on neuromorphic processors. However, this hardware-level reliance on sparsity introduces a severe, domain-specific security vulnerability: the direct, proportional relationship between network activity and physical power consumption allows adversaries to craft input perturbations that force silent saturation. New research from Raptis and Stratigopoulos shows that white-box attackers can bypass traditional, correctness-based anomaly detection systems by inflating the energy consumption of deployed SNNs without altering their output classifications.

| | |
|---|---|
| **Attacker** | White-box access (knowledge of model architecture, weights $\theta$, and neuron parameters). |
| **Victim** | Edge-deployed SNNs on event-driven neuromorphic hardware (e.g., Intel Loihi-1) processing native event streams. |
| **Goal** | Maximize inference-time synaptic operations (SynOps) and physical energy consumption while preserving model accuracy and decision latency. |
| **Budget** | High offline computation for universal mask design, or extensive per-input GPU optimization (e.g., up to ~4 minutes on an Nvidia A100) for the per-sample baseline. |

## Background and Problem Setup

SNNs achieve energy efficiency by communicating via sparse, binary temporal events (spikes) rather than dense, continuous activations. On neuromorphic architectures like Intel's Loihi-1 or IBM's TrueNorth, a silent neuron consumes virtually zero dynamic energy, while active neurons trigger Synaptic Operations (SynOps). 

In traditional Artificial Neural Networks (ANNs), sponge attacks typically target architectural bottlenecks (such as early-exit thresholds) or activation sparsity on hardware accelerators that skip zero-valued operations. In contrast, SNNs present a continuous, input-dependent energy profile directly proportional to the total spike count. 

Prior work in the SNN domain has focused on rate-coded networks or weight poisoning rather than native event-driven streams where the input alphabet is strictly binary, and clean inputs are highly sparse.

## Methodology

Native event-based datasets represent inputs as binary spatio-temporal tensors:

$$\mathbf{x}_0 \in \{0, 1\}^{C \times H \times W \times T}$$

where $C$ represents the input channels (such as on/off polarity for event-based cameras), $H \times W$ is the spatial resolution, and $T$ is the number of temporal steps. Because the input is binary, continuous gradient descent is impossible without a differentiable surrogate.

### The Per-Sample Attack

To optimize the binary input space, the authors define a continuous parameter tensor of logits $P \in \mathbb{R}^{C \times H \times W \times T}$. They then generate a soft mask $m$ utilizing Gumbel-Softmax:

$$\mathbf{m} = \epsilon \cdot \text{GumbelSoftmax}(\mathbf{P}; \tau)$$

Using a symmetric flip rule, this mask is applied to the clean input $\mathbf{x}_0$:

$$\mathbf{\tilde{x}} = \mathbf{x}_0 + (\mathbf{1} - \mathbf{x}_0) \odot \mathbf{m} - \mathbf{x}_0 \odot \mathbf{m}$$

To step back into the binary domain during the forward pass while preserving gradient flow during the backward pass, a Straight-Through Estimator (STE) binarizes the input at a threshold of 0.5:

$$\mathbf{x}_{\text{sponge}} = \text{STE}(\mathbf{\tilde{x}})$$

The optimization is driven by a composite loss function designed to maximize internal network spikes while preserving the classification output and minimizing the $L_0$ input perturbation footprint:

$$\mathcal{L} = w_{\text{var}} \mathcal{L}_{\text{var}} + w_f \mathcal{L}_{\text{force}} + w_p \mathcal{L}_{\text{pres}}$$

- **Sponge Term ($\mathcal{L}_{\text{force}}$)**: A piecewise-linear hinge loss driving every neuron $n$ in every layer $\ell$ to fire at its maximum theoretical capacity $T$:
  
  $$\mathcal{L}_{\text{force}} = \sum_{\ell=1}^{L} \sum_{n=1}^{n_\ell} \max\left(0, T - \sum_{t=1}^{T} \mathbf{s}_{n,t}^{(\ell)}(\mathbf{x}_{\text{sponge}})\right)$$

- **Preservation Term ($\mathcal{L}_{\text{pres}}$)**: A reciprocal surrogate that forces the network to sustain high spike counts for the clean-predicted target class $y^*$:
  
  $$\mathcal{L}_{\text{pres}} = \frac{1}{\mathbf{z}_{y^*}^{(L)} + \varepsilon_{\text{div}}}$$

- **Variance Regularizer ($\mathcal{L}_{\text{var}}$)**: Minimizes the variance of the difference tensor $\mathbf{x}_0 - \mathbf{x}_{\text{sponge}}$, serving as a soft $L_0$ penalty to preserve input stealth.

```python
# Conceptual optimization loop for Per-Sample Sponge Attack
def optimize_per_sample(x_0, model, w_var, w_f, w_p, scale_eps, n_iter):
    # Initialize logit parameters
    P = initialize_logits_normal(x_0.shape)
    best_loss = float('inf')
    best_x_sponge = None

    for it in range(n_iter):
        tau = get_temperature_schedule(it)
        
        # Gumbel-Softmax projection and symmetric flip
        m = scale_eps * gumbel_softmax(P, tau)
        x_tilde = x_0 + (1 - x_0) * m - x_0 * m
        x_sponge = straight_through_estimator(x_tilde)
        
        # Forward pass and metrics capturing
        outputs, intermediate_spikes = model.forward(x_sponge)
        
        # Compute loss components
        l_force = compute_hinge_loss(intermediate_spikes, max_steps=T)
        l_pres = 1.0 / (outputs[clean_class_index] + 1e-7)
        l_var = compute_variance(x_0 - x_sponge)
        
        total_loss = w_var * l_var + w_f * l_force + w_p * l_pres
        
        if total_loss < best_loss:
            best_loss = total_loss
            best_x_sponge = x_sponge
            
        # Backward pass & Adam step on P
        gradients = backpropagation(total_loss, P)
        P = adam_update(P, gradients)
        
    return best_x_sponge
```

### The Universal Attack

A real-world attacker cannot run a multi-iteration gradient optimization loop on-the-fly during streaming edge inference. To address this, the authors propose a universal sponge attack that generates a single, fixed binary mask $\mathbf{U} \in \{0, 1\}^{C \times H \times W \times T}$ offline.

1. **Gradient Gathering**: Using a tiny training subset $\mathcal{D}_{\text{train}}$ (only 10 samples per class, yielding $M=100$ to $200$ samples), the attacker runs a forward and backward pass to accumulate gradients of the sponge loss term:
   
   $$\mathbf{g} = \frac{1}{M} \sum_{i=1}^{M} \nabla_{\mathbf{x}} \mathcal{L}_{\text{force}}(f_{\theta}(\mathbf{x}^{(i)}))$$

2. **Binarization**: The accumulated gradient is normalized to unit standard deviation ($\mathbf{\tilde{g}} = \mathbf{g} / (\text{std}(\mathbf{g}) + \epsilon_{\text{div}})$). A flip logit is constructed:
   
   $$\ell_g = -\varepsilon \mathbf{\tilde{g}} + b$$

   where $\varepsilon$ controls the gradient strength and $b$ acts as a sparsity bias. This is converted to a binary mask $\mathbf{U}$ via Gumbel-Softmax and thresholded at 0.5.
3. **Application**: At runtime, the mask is injected via a computationally negligible bitwise XOR operation:
   
   $$\mathbf{x}_{\text{sponge}} = \mathbf{x}_0 \oplus \mathbf{U}$$

## Limitations & Open Questions

- **Stealth Trade-off in Universal Sponges**: While the per-sample attack exhibits near-perfect preservation ($\ge 98.48\%$), the computationally viable universal attack suffers from noticeable accuracy drops. For example, on the Spiking Heidelberg Digits (SHD) dataset, classification accuracy drops by $10.35$ percentage points under the universal mask. In critical edge systems, this degradation might alert administrators to model malfunction.
- **Strict White-Box Assumptions**: Generating both the per-sample and universal perturbations relies on access to SNN weights $\theta$ and network architecture. How effectively these binary masks transfer in a black-box setting remains an open question, and binary input patterns typically show lower transferability than continuous ones.
- **Simulated Hardware Metrics**: The energy figures are extrapolated based on nominal Loihi-1 benchmarks ($23.6\text{ pJ}$ per SynOp). They do not incorporate physical hardware quirks, such as dynamic memory bottlenecks, leakage current fluctuations, or state-update energy when processing extremely dense streams.

## What Practitioners Should Do

SNN deployment teams must look beyond standard accuracy metrics to defend against energy-exhaustion attacks:

1. **Implement Input-Sparsity Monitors**: Because event-driven sensors are naturally sparse, deployment pipelines should enforce an upper bound on input event density. If an incoming sample exceeds typical temporal or spatial spike count limits (e.g., matching the $L_0$ perturbation levels shown in Table III), it should flag a physical security warning.
2. **Apply Spike-Rate Regularization During Training**: Train SNN models using strong activity penalty constraints (L1 or L2 regularization on internal neuron firing states). Restricting the maximum allowable firing capacity makes it much harder for gradient optimization to discover low-loss sponge regions.
3. **Deploy Neuromorphic Firewalls**: Incorporate lightweight preprocessing stages on the neuromorphic hardware. This could include a dynamic spike rate filter or a simple physical "cooldown" phase on input channels that exhibit continuous, non-decaying activity (which is typical of the universal XOR mask).

## The Takeaway

Sparsity is the foundation of SNN efficiency, but this research highlights that it is also their primary algorithmic vulnerability. By shifting the threat model from accuracy manipulation to energy exhaustion, universal sponge attacks prove that edge devices can be targeted for premature battery drain with zero online computational cost.

## Den's Take

We need to be honest about the paper’s core weakness: the computational asymmetry completely breaks the threat model. The per-sample attack’s reliance on four minutes of Nvidia A100 compute to perturb a single event stream is an absurdity for real-time edge exploitation. Meanwhile, the realistic, zero-online-compute universal XOR mask only achieves a 1.24$\times$ energy inflation—a marginal 24% increase that is unlikely to cause immediate failure on milliwatt-scale neuromorphic chips.

Furthermore, this threat model misses a fundamental hardware reality. Physical Dynamic Vision Sensors (DVS) routinely run hardware-level refractory filters and background activity denoisers to prune hot pixels and high-frequency noise. A static, high-frequency XOR mask would likely get scrubbed at the sensor level before it ever registers a synaptic operation on the SNN. 

As I often note when reviewing edge AI security, physical hardware constraints consistently dilute theoretical edge exploits. SNN security researchers need to stop evaluating attacks solely in idealized software simulators and start testing against the hardware-level filters of actual neuromorphic pipelines.
