# Amplification of PII Leakage via LLM-Generated Fine-Tuning Data

## TLDR
*   Fine-tuning on LLM-generated data increases privacy risks.
*   Developers using synthetic data for domain adaptation are at risk.
*   PII extraction success rate on Pythia increased by over 20%.

## Synthetic Data and the Privacy Gap

The process of tailoring Large Language Models (LLMs) to specific domains often involves fine-tuning on specialized datasets. Historically, using real-world data carries inherent privacy risks, which researchers address by substituting real data with synthetic, or generated, data. The assumption underpinning this substitution is that data generated by an LLM is sufficiently distinct from proprietary or sensitive real-world data. However, the paper argues this assumption is flawed. As LLMs become more capable, the distinction between generated and real data blurs, meaning that synthetic data inherits and potentially exacerbates privacy concerns. This work specifically targets the gap where developers rely on LLMs to generate domain-specific data for fine-tuning, believing this process mitigates privacy risks associated with the original training set. The study investigates how this reliance on generated data impacts two common fine-tuning paradigms: supervised fine-tuning (SFT) with unstructured text, and instruction tuning via self-instruct.

## Unstructured Data and PII Amplification

When SFT is performed using unstructured, plain-text data generated by an LLM, the privacy risk demonstrably increases. Following the setting in former work [17], the Enron email dataset was used to evaluate the potential privacy risks on fine-tuned Pythia models. First, Pythia-12b was used to generate an email dataset, and then the Pythia model was fine-tuned with different model sizes on these generated datasets. PII attacks were conducted following Wang et al.’s [54] setting on both the pre-trained model and fine-tuned models. The results demonstrate that supervised fine-tuning amplifies privacy risks even in unstructured generated data (Section 3.3). Specifically, the rate of successful PII extractions for Pythia increased by over 20% when fine-tuned with unstructured generated data compared to the pre-trained state. This shows that training on generated raw data within the same domain can significantly amplify the privacy leakage associated with the LLM’s pre-training datasets.

## Self-Instruct Tuning and MIA Score Elevation

A separate pipeline examined the risks associated with instruction-based tuning, specifically the self-instruct procedure. Here, the process begins by defining seed tasks based on a sensitive legal domain, using the FreeLaw subset of The Pile. In line with the self-instruct procedure, LLama-3 was prompted with these seed tasks to procure the generated data for fine-tuning, including task descriptions, related information, and answers. These generated examples were then used to fine-tune Pythia models. The privacy evaluation focused on Membership Inference Attacks (MIA) using a score-based method. The results reveal that the AUC ROC score of MIA on FreeLaw datasets enjoys nearly 20% improvement compared to the pre-trained model. This suggests that the quality and similarity of the generated data to the original pre-training datasets are the primary drivers in exacerbating these privacy risks in instruction-tuned models.

## Limitations

The study focuses on two specific fine-tuning paradigms (SFT/unstructured and self-instruct/instruction-based) and relies on established PII extraction and MIA attack vectors. The threat model assumes attackers can query the API or access output logits; more complex, adversarial access scenarios are not covered. Furthermore, the analysis hinges on the observation that high-quality generated data closely mirrors pre-training data, an assumption that may weaken if generation quality degrades or if the model is deployed in environments where data provenance is strictly controlled.

## What practitioners should do

*   Do not assume synthetic data generation eliminates privacy risks when fine-tuning LLMs.
*   If using SFT, rigorously test fine-tuned models with PII extraction attacks against known sensitive data structures.
*   When employing self-instruct tuning, treat the generated data quality as a primary security input, not just a performance boost.
*   Be aware that instruction tuning on domain-specific data can increase MIA vulnerability scores, as seen with the 20% AUC-ROC increase on Pythia-6.9b.

## Verdict

Read this paper if you are engineering LLM fine-tuning pipelines; otherwise, skip it. It provides concrete quantitative evidence that synthetic data generation is not a privacy shield.

## Den's Take

The paper correctly identifies that using LLM-generated data as a privacy substitute during fine-tuning is a flawed security assumption. However, the focus remains too heavily on the *amplification* of existing risks rather than the *introduction* of new failure modes. I predict that the most immediate, unaddressed danger is the creation of highly specific, brittle knowledge artifacts. When LLMs generate data based on a seed set, they are not just replicating PII; they are creating synthetic "shortcuts" in the model's parameter space that are extremely susceptible to adversarial manipulation, far beyond simple PII extraction. The evaluation is limited to established attack vectors, which is a weakness. If the model's internal state is hardened against these known extraction methods, the induced fragility from synthetic data could lead to novel, targeted prompt injection vectors that exploit the learned synthetic correlations. This mirrors the architectural brittleness I observed in agent systems, where superficial evaluation masks deeper state compromises.
